# 风险分级模型路由

模型选择由任务风险决定，不由文件数量、回复长度或表面复杂度决定。Skill 可以建议或记录所需档位；只有运行环境提供模型切换能力时才能实际切换。无法切换时，明确采用更严格的复核方式，不假装已经切换。

## 三个档位

### 判断档

用于可能改变业务事实或后续架构的工作：

- 规则、状态、权限、责任归属；
- 跨模块边界与正式结果；
- 页面身份、融合、删除和独立页面反证；
- 冲突裁决、异常闭环和最终硬闸门验收；
- 用户要求对方案进行强反证。

优先使用当前可用的高推理模型或最高合理推理档位。若项目环境可选模型，优先能力最强的推理型模型；具体型号不写死在主 Skill 中。

### 推进档

用于已有边界内仍需局部判断的工作：

- 单页逻辑逐项推进；
- 已确认规则下的信息架构整理；
- 桩子登记和局部一致性检查；
- 文档更新前的影响分析。

使用平衡型模型或中等推理档位，并对涉及状态、权限、跨模块的局部结论升级到判断档。

### 机械档

只用于不产生新业务判断、结果可确定性验证的工作：

- 已确认术语的全局替换；
- 索引、链接、版本号和格式同步；
- 搜索旧名称残留；
- 运行校验、生成清单、核对 Git 状态。

使用经济型模型或低推理档位。机械档不得解释含义不明确的文本，不得自行消解冲突，也不得把缺口补成规则。

## 升级触发器

无论当前档位为何，出现以下情况立即升级到判断档：

- 两份当前有效文件互相冲突；
- 用户方案与已确认规则冲突；
- 无法判断事项是正式规则还是桩子；
- 一个动作缺少角色、触发、退出或结果回写；
- 需要推导未启动 Web、相邻模块或未登记能力；
- 删除或融合页面可能导致职责无人承载。

## 降档条件

只有同时满足以下条件才可降到机械档：

- 输入结论已经确认；
- 输出形式唯一或有明确模板；
- 不需要解释含义、选择方案或补足缺口；
- 结果可以通过搜索、校验器或固定清单验证；
- 失败不会静默改变业务事实。

## 记录方式

大型复盘或硬闸门记录可注明：

- 本次任务档位；
- 触发依据；
- 是否发生升级；
- 采用的验证方式。

不要在每条普通回复里展示模型名或制造额外噪音。只有选择影响成本、速度或可靠性时才向用户说明。
