# 推进业务模块

将项目文件视为跨任务记忆，将 Skill 视为推进工作流。不要把聊天长度或当前模型记忆当成事实来源。

## 1. 识别范围

1. 找到项目根目录。
2. 读取 `docs/00-当前范围与模块登记.md`。
3. 确认用户指定的模块、所属端和本次阶段。
4. 若模块未登记、仍是概念阶段或所属端未启动，只进行范围澄清和规则访谈；不得自动建立页面、状态、代码、接口或后台能力。

## 2. 接管已有模块

读取目标模块的 `00-START-HERE.md`，先输出一段简短接管摘要：

- 当前模块和所属端；
- 当前推进阶段；
- 本次实际读取的有效文件；
- 已知未决问题；
- 本次明确不进入的范围。

若找不到总池，先盘点已有资料并请用户确认其成熟度，再决定是否实例化；不要从文件编号、行业惯例或其他模块反推。

## 3. 按需加载资料

只读取完成当前任务所需的最小集合：

- 规则讨论：总池首页、当前规则、直接相关接口；
- 页面设计：再读取设计进度、页面清单、页面流程和目标页面资料；
- 代码实现：再读取当前设计与真实代码入口；
- 验收：再读取验收对象、规则依据和已确认接口。

历史池默认不读。只有追溯冲突或版本来源时才读取，并且不得让历史覆盖当前有效文件。

## 4. 继承跨模块内容

只通过已确认接口继承前一模块的结果：

- 读取来源模块在接口池中明确输出的对象、状态或结果；
- 读取目标模块明确接收的内容；
- 不把来源模块的内部流程、页面和操作复制到目标模块；
- 关联模块尚无总池或接口未确认时，将其标记为待讨论，不自行补全。

例如，手术植入可以接收手术通知已确认的来源订单和候选实物，但不能因此继承手术通知的完整要货、履约和结余流程。

## 5. 按阶段推进

通常按以下顺序推进：

1. 业务规则与边界；
2. 规则封板与验收；
3. 信息架构；
4. 页面清单；
5. 页面流程；
6. 低保真结构；
7. 视觉稿；
8. 代码实现；
9. 模块验收与跨模块联调。

从资料池标注的当前阶段继续，不重做已完成阶段。每次只推进用户明确指定的一项；发现冲突时暂停下游制作，先回到规则层确认。

## 6. 执行组间切换筛查

完成任意一组页面的逻辑讨论后，在开启下一组之前必须执行硬闸门：

1. 读取模块首页登记的全部当前有效文件和直接相关接口；组间切换是“最小读取”原则的明确例外；
2. 盘点模块全部已知文件，核对当前池与历史池身份、替代关系和引用方向；历史池默认只检查目录与引用，发现具体冲突后才读取必要正文；
3. 检查页面身份、入口、返回、状态、任务、角色权限、结果回写、术语、页数、版本和当前唯一任务能否闭合；
4. 搜索旧页面名、旧状态词、旧流程和被替代结论在当前有效文件中的残留；
5. 检查有效结论是否已同步到规则、接口、页面清单、页面流程、设计总控、当前进度与模块首页的适用位置；
6. 不搜索或读取旧任务聊天。只检查是否存在依赖聊天记忆或尚未沉淀的结论；聊天独有内容按未确认缺口处理；
7. 在当前阶段资料池形成组间切换筛查记录，列明范围、发现、修复、暂缓和结论。
8. 筛查通过并完成全部资料对齐后，若项目配置了Git远端，必须在开启新组前完成远程同步：限定暂存本次模块及项目规则文件，排除无关改动；获取远端引用并检查分叉；提交、推送并验证远端包含该提交。同步失败或无法验证时停止切换并报告阻塞。

存在阻塞冲突时，不得开始下一组。非阻塞缺口必须登记明确归属，不能在下一组中静默补写。

## 7. 执行新组开启宏观审查

组间切换筛查通过后，先执行新组宏观审查，不能直接逐页讨论：

1. 从全部当前有效资料中提取该组的业务目标、核心对象、起止条件、角色责任、入口出口、形成结果、跨组交集和明确边界；不得读取旧任务聊天补背景；
2. 若已有候选页面，建立整组处置矩阵，对每页判断保留、融合、修改、删除或条件性出现，并检查组内及跨组职责重复、信息重复、动作错位和结果回写断裂；
3. 若完全没有候选页面，先建立用户问题与业务能力清单，不从模板或惯例生成页面；
4. 对每项能力比较融入现有页面、条件区块、共用组件或独立页面四类承载方式；
5. 独立页面必须具备独立上下文、稳定进入条件、明确本人动作、清晰返回和结果回写，且现有页面或轻量组件无法清楚承载；
6. 发现规则缺口时先回规则层，不用页面设计静默补全；
7. 在当前阶段资料池形成新组宏观审查记录，列明继承事实、整组职责、对象与结果、跨组交集、候选页面处置、缺口、推荐方案和待确认项。

宏观方案经用户确认前，不得默认保留旧页数，不得建立未经确认的新页面编号，也不得进入单页结构、低保真或视觉设计。

## 8. 沉淀结果

任务形成有效结论后：

1. 更新对应规则、接口、设计、代码或验收子池；
2. 更新模块总池首页的当前版本、未决问题和下一步；
3. 被替代文件移入决策与历史池并注明替代关系；
4. 跨模块影响只更新已确认接口，不擅自改写另一模块；
5. 新模块或成熟度变化先更新范围登记。

总池保存“现在相信什么”，历史池保存“为什么走到这里”，Skill 保证“下一次怎样继续”。
