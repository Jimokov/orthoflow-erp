# 库存管理推进总则 v0.1

> 状态：当前有效、已确认（2026-08-28）的模块推进控制资料；不承载库存业务规则。

## 1. 事实分层

- 本模块规则池与接口池只保存已经确认的库存事实与契约。
- 手术通知、手术植入的当前有效正文是外部事实来源；库存只继承其已确认输入、输出、责任与回写边界。
- [库存管理候选资料归档](../../docs/跨模块候选资料/库存管理候选资料归档-v0.1.md)只定位已确认外部约束与稳定桩子；[探索候选簿](../../docs/跨模块候选资料/库存相关探索候选簿-v0.1.md)只保存待论证候选。二者均不替代库存规则。
- 用户本轮描述、探索推演和页面样例均先标明为待确认输入；未经确认，不写为规则、接口、状态、权限或正式结果。

## 2. 推进顺序与停止条件

1. 先完成本文件与《启动前全量排查与承接基线审校》的用户确认；
2. 再进行业务边界与核心对象澄清；
3. 形成第一条库存规则前，明确来源、对象、责任、正式结果、跨模块影响与桩子；
4. 影响手术通知或手术植入的输入、输出、责任或回写，先回到双方接口资料共同确认；
5. 规则与接口稳定前，不进入页面、流程、低保真、代码、自动化或 Web 后台设计。

出现资料冲突、需依赖旧聊天、或无法区分外部约束与库存内部规则时，暂停受影响结论；不以行业惯例补全。

## 3. 本轮推进主题

首个主题是“业务员自有库”的业务边界、建立条件与核心对象。当前规则基线中的 I-K01—I-K06 仅为待确认输入，审查时不得将任何一条视为已确认事实。

## 4. 本轮确认结果

- 2026-08-28，用户确认本文件与《启动前全量排查与承接基线审校 v0.1》作为库存管理功能模块的启动控制基线。
- 确认只放行进入“业务边界与核心对象澄清”，不确认 I-K01—I-K06，也不产生库存内部规则、页面、流程、接口协议或 Web 后台能力。
