# 业务员侧常备物资业务边界与核心对象 v0.1

> 状态：当前有效；确认日期：2026-08-28。
> 身份：阶段 1 的边界与对象确认正文；不定义库存操作、盘点、扣减、补货、审批、页面或 Web 后台。

## 1. 当前确认的概念边界

- “业务员侧常备物资”是本模块当前采用的工作范围，用于描述业务员日常手术可能使用、但不位于公司总库的常备实物集合。
- 该范围包含两种保管形态：医院托管的寄售类物资，以及业务员自行携带或保管的物资。
- 两种保管形态统一归入同一业务用途和对外来源，不等于业务员具有法律所有权，也不代表公司已经建立正式寄售制度。
- “自有库”“个人仓”暂作为历史／非标准称呼保留，不作为本模块已确认的正式仓库或所有权对象。

## 2. 对外来源与不足边界

- 对手术植入，业务员侧常备物资统一作为一个对外来源；医院托管与业务员自持的区别暂保留在库存内部边界，不拆成两个对外来源。
- 当业务员侧常备物资不能满足本次手术需求时，缺口由手术通知承接补全；公司采用采购、调拨或其他履约方式不改变该对外边界，也不成为业务员在库存管理功能模块中的操作选择。
- “不能满足”的判定条件、可用性计算、数量扣减、补回和正式回写仍待后续规则与接口阶段确认。

## 3. 核心对象边界

| 对象／层次 | 当前确认边界 | 尚未确认 |
|---|---|---|
| 业务员侧常备物资 | 业务员日常手术的常备实物来源集合 | 是否需要公司资格、登记或批准后才纳入范围 |
| 保管形态 | 医院托管、业务员自持；属于同一对外来源下的内部区别 | 两种形态在可用性、责任、盘点和补回上的具体差异 |
| 实物身份 | 产品、批号／可追溯身份（如有）与数量，沿用手术植入的来源追溯边界 | 拆盒、细分分摊、器械包放行等细则 |
| 手术通知补全 | 库存不足后的缺口承接归手术通知；采购／调拨方法不向业务员暴露 | 不足判定、触发时点、回写结果和失败恢复 |
| 基础盘点 | 暂不建立正式对象或结果，仅保留为涉及后台与总库规则的桩子 | 盘点范围、责任、锚点生效、差异和旧版存量衔接 |

## 4. 明确不包含

- 不确认医院托管物资的法律所有权、正式寄售合同或财务责任。
- 不把医院托管或业务员自持直接等同于“个人仓”或公司已认可的可用库存。
- 不定义入库、出库、调拨、库存扣减、最低库存、自动补货、审批或 Web 后台。
- 不复制手术通知订单状态机、页面任务，也不改写手术植入来源规则；术语映射留在后续跨模块接口澄清。

## 5. 当前桩子与下一步

- P-K01：自有库、个人仓与业务员侧常备物资的正式术语映射。
- P-K02—P-K08：审批、可用量、扣减与恢复、来源识别、器械放行、异常、还回及技术控制等后续问题。

下一步先确认两种保管形态在“可用性、业务员责任、实物追溯”三项上是否存在会改变正式结果的差异；若没有，则继续作为同一来源下的内部属性，若有，再回到规则与接口层拆分。
