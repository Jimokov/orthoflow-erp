# C11 需求模板逻辑 v0.1

> 状态：单页逻辑已确认，完整需求摘要等待组配方案回补
> 更新日期：2026-08-18
> 范围：只定义业务员APP侧C11单页逻辑；不制作低保真，不展开Web审核、计费或套餐

## 1. 页面身份

C11是C00“从模板创建”的下级模板选择与本人模板申请载体，不与C00并列为新的创建主线，也不是公司模板审核后台。

页面首先帮助业务员快速找到一个可用模板并开始本次需求；模板候选创建、续编和申请结果属于同页内的低频次级管理，不得反过来压过当前订单创建任务。

## 2. 必须继承的对象与边界

| 对象 | C11中的身份 |
|---|---|
| 公司共享模板 | 公司已经发布、业务员当前有权浏览和使用的正式模板资产 |
| 已下载模板 | 共享模板在本人账号下的可用副本；保留来源、版本和公司可用状态，不是私人模板 |
| 未提交模板候选 | 业务员尚未提交审核的模板编辑结果；只在C11继续，不进入C10 |
| 本人模板申请 | 已经提交公司的候选及其审核结果；不等同于可用模板集合 |

C11不建立未经审核即可长期复用的私人模板库，不携带订单编号、具体手术日期与时间、履约、任务、患者或实物事实，也不推演公司管理人员的审核页面与内部流程。

## 3. 已确认的信息主次

C11保持一个页面、两个层级，不把四类对象做成四个同等重量的页签。

### 3.1 第一层：选择模板创建需求

这是从C00进入C11后的默认任务，承载：

- 浏览和查找公司共享模板；
- 查看本人已下载模板；
- 选择一个模板形成本次订单草稿；
- 进入C02后核对本次手术信息和需求，并最终经过C09正式提交。

公司共享模板和已下载模板虽然来源不同，但都服务于同一个问题：“这次用哪个模板开始”。两者可以在第一层内切换或分区，不能被拆成两套创建流程。

第一层采用两个轻量切换项：

1. **已下载**：本人已经选择并绑定到账号的模板集合；存在已下载模板时默认打开；
2. **公司模板**：本人当前有权浏览和使用的公司共享模板库；没有已下载模板时直接打开，不先展示空白的“已下载”。

两项只切换模板集合，不改变创建流程，也不是两个独立页面。页面不为了保持机械一致而强迫业务员多经过一次空状态。

两类模板统一只提供一个主动作“使用模板”。使用后进入C02填写本次手术信息并核对、调整需求，因此不另设语义重复的“直接使用”和“调整使用”。

- 公司模板上的“下载”是次级动作；下载成功后保留当前浏览位置，不强制跳到“已下载”；
- 已下载模板上的“移除下载”进入低频更多操作；移除只删除本人侧副本，不影响公司模板；
- 公司模板存在更新、停用或基础资料失效时，只在相关模板上显示必要状态和处理结果，不另建状态页面；
- 已下载副本再次使用前仍按公司版本和当前可用性校验，不能因为已经下载而绕过停用或失效规则。

### 3.1.1 模板卡片与搜索

模板卡片只显示识别、判断是否适用和进入下一步所需的信息：

- 模板名称作为主识别信息；
- 模板已有的适用医院、科室、术者按实际内容显示，缺失项不占位；
- 显示一行紧凑的产品与器械需求摘要，不在列表卡片铺开完整需求清单；
- 只在相关时显示“有更新”“已停用”“资料需重新匹配”等必要状态；
- 不展示审核人、内部版本号、使用次数、公司治理过程或其他后台信息。

产品与器械摘要的具体字段、数量表达和组间关系等待C02／C03组配方案回补。C11当前只冻结“紧凑摘要用于识别、完整内容使用前可查看”，不提前定义组配结构。

搜索覆盖模板名称、医院、科室、术者及产品／器械名称。当前不增加高级筛选、排序面板或公司内部分类条件；搜索只帮助找到模板，不生成新的业务对象或私人收藏体系。

### 3.1.2 个人备注

公司共享模板和已下载模板都允许业务员添加“个人备注”。个人备注是附着在公司模板身份上的本人辅助信息，不是模板正式内容，也不构成未经审核的私人模板：

- 公司模板无需先下载即可添加个人备注；添加备注本身不使其进入“已下载”；
- 同一业务员对同一来源公司模板只保留一条个人备注，在“公司模板”和“已下载”两处显示同一内容，不生成两份备注；
- 个人备注按本人账号私有保存并在设备缓存，避免换设备、重新登录或清理缓存后无故丢失；
- 移除下载不删除个人备注，删除备注必须由本人明确执行；公司模板更新后备注继续绑定该模板；
- 搜索可以命中个人备注，帮助本人按自己的使用习惯查找模板；
- 个人备注不修改公司模板，不进入模板申请或公司审核，也不自动带入订单草稿、C09整单额外要求或未来模板固定要求；
- 个人备注不得用于记录患者姓名、住院号等患者信息，编辑位置提供轻量提示。

面向业务员使用“个人备注”，不使用容易被理解为仅保存在当前手机上的“本地备注”。

### 3.1.3 使用前查看

- 点击模板卡片在C11当前页面打开轻量详情，不新增独立模板详情页；
- 轻量详情显示模板已有的适用信息和完整需求内容，并保留唯一主动作“使用模板”；
- 卡片上的“使用模板”也可以直接进入C02，因为此时只形成可编辑订单草稿，不会正式提交；
- 已停用模板不能使用；有更新或资料需重新匹配时明确提示，并在进入C02后按最新版本和当前基础资料继续核对；
- 轻量详情不提供正式订单提交、模板审核或公司治理动作。

### 3.2 第二层：我的模板申请

这是低频管理层，承载：

- 从空白或现有模板主动创建模板候选；
- 继续尚未提交的模板候选；
- 查看本人已经提交的模板申请及审核结果。

面向业务员不必持续暴露内部过程词“候选”。入口与结果表达优先使用“创建需求模板”“未提交模板”“我的模板申请”等直接语言。

第二层顶部提供“创建需求模板”，下方仍使用一个列表，按是否需要业务员继续处理分为三层，不建立状态页签：

#### 未完成

- **未提交模板**：可以继续编辑，也可以确认删除；删除只清理从未正式提交的模板候选；
- **退回待修改**：显示公司提供的退回原因，可以继续修改并重新提交；不再处理时使用“放弃申请”正式结束，不能用普通删除抹掉已经发生的提交与退回记录；
- 同层按最后更新时间倒序。

#### 审核中

- 显示提交内容与提交时间，只读等待公司结果；
- 当前不提供编辑、删除或撤回，避免本人内容与公司正在审核的版本不一致；
- 审核中不形成业务员待办。

#### 申请结果

- **已发布**：可以进入对应公司模板并使用或下载；
- **已合并**：显示最终归入的公司模板，允许查看该模板；
- **未保留**：显示公司结果；公司提供原因时一并展示；
- **已放弃**：保留申请历史，不再提供继续操作；
- 结果层位于列表末端并默认收起，同层按最后更新时间倒序。

第二层不得进入G04“我的”，也不得在C11首屏与“选择模板创建需求”争夺相同视觉重量。未提交和退回待修改只在C11入口显示低强调的“未完成”数量，不进入G03“待我处理”：模板申请不影响当前订单，也不存在必须立即完成的履约责任。是否使用普通系统通知提示退回，留到统一通知规则阶段。

### 3.3 模板正式内容

模板正式内容与个人备注严格分开。提交公司审核的模板候选包含：

- **模板名称**：必填；
- **适用医院、科室、术者**：均为可选，允许建立不绑定具体医院或术者的通用模板；
- **产品与器械需求**：至少存在一个产品需求组或器械需求组；具体组配结构等待C02／C03方案回补；
- **固定要求**：可选，只保存能够跨多次手术复用的稳定要求。

模板不得包含具体手术日期与时间、订单编号、患者、履约、批次、任务、异常或实物信息。

从正式订单成功提示创建模板时，可以带入医院、科室、术者以及当前正式有效的结构化产品／器械需求，但不自动复制该订单的“整单额外要求”。业务员需要明确整理希望长期复用的内容并填写为“固定要求”，避免某一单的临时、紧急说明污染模板。

使用模板创建订单时，“固定要求”预填到C09“整单额外要求”，业务员仍需结合本次订单重新核对和修改。个人备注始终不自动带入。

### 3.4 候选形成、自动保存与退出

- 从空白进入C02模板编辑态时，仅打开页面不形成“未提交模板”；产生实际输入并在本机持久保存成功后，才在C11“未完成”中形成可见记录；
- 基于现有模板或订单成功提示创建候选时，带入的有效内容在本机首次持久保存成功后形成可见记录，不因点击入口制造尚未保存的空记录；
- 模板候选继承C02的本机持久保存与公司端同步边界：离线可以编辑、保存和退出，尚未同步时低强调显示“待同步”，正式提交公司审核必须联网；
- 模板候选始终由C11管理，不进入C00最近草稿或C10全部草稿，也不与订单草稿混排；
- 从C11主动创建、基于现有模板创建或继续未完成／退回申请时，中途退出返回C11“我的模板申请”并恢复原列表位置；C03局部编辑先返回C02，再由C02退出；
- 从新主订单O01的一次性成功提示进入时，中途退出返回来源O01；只要候选已成功保存在本机，之后仍可从C11继续，O01一次性入口不因此恢复或常驻；
- 本机保存失败时不得静默退出；应保留当前内容并提供重试，或由业务员明确确认不保存退出。

### 3.5 正式提交、成功反馈与退回重提

- 模板候选在C02模板编辑态直接使用“提交公司审核”，不进入C09，也不生成订单；
- 点击提交时校验模板名称、至少一个编辑完整的产品或器械需求组，以及当前候选版本和相关基础资料的可用性；
- 正式提交前只显示一次轻量确认，说明“审核期间不可修改，公司决定是否进入共享模板库”，不展开审核角色、内部步骤或治理规则；
- 正式提交必须联网并防止重复提交；网络、版本或服务失败时停留在当前候选并保留输入，不生成重复申请；
- 成功后不新增成功页：从C11进入的返回C11并将原记录更新为“审核中”；从O01一次性提示进入的返回来源O01，只显示低强调“已提交审核”，申请仍可在C11查看；
- 公司退回后继续编辑沿用原申请身份；重新提交形成该申请的新版本，不另建第二条申请，原提交、退回原因和重提历史继续保留。

## 4. 已确认的进入与结果关系

```text
C00 从模板创建
→ C11 第一层选择模板
→ C02 订单草稿来源态
→ C03 按需编辑需求组
→ C09 核对并提交
→ 新O01
```

- 使用共享模板和使用已下载模板进入同一套C02／C03／C09创建链；两类模板都只使用“使用模板”一个主动作；
- 创建或续编模板候选时复用C02／C03模板编辑态，不生成订单草稿、不进入C10，也不经过C09；
- 模板候选提交形成模板申请，不直接成为共享模板，也不影响任何订单提交结果；
- 从新主订单首次提交成功提示进入模板候选编辑，仍属于同一套候选能力，不在O01建立永久模板入口。

## 5. 明确不包含

- 不建立四个并列主标签页；
- 不把C11做成模板统计、运营或审核看板；
- 不在C11展示正式订单、订单草稿、履约或待我处理；
- 不设计管理人员审核角色、审核动作和Web页面；
- 不设计下载额度、付费解锁、支付或套餐；
- 不恢复历史C11旧结构。

## 6. 阶段性收束与回补口

| 检查项 | 结论 |
|---|---|
| 页面身份 | C11是一页两层；模板选择为主，候选与申请管理为低频次层 |
| 对象边界 | 共享模板、已下载模板、未提交候选与本人申请身份清楚，不建立私人模板库 |
| 内容边界 | 模板正式内容、固定要求和个人备注已经分开 |
| 保存退出 | 空记录不落库；本机保存、同步、离线续编及三类来源返回已经闭合 |
| 正式提交 | C02模板态直接提交审核；联网、校验、防重复、成功去向和退回重提已经闭合 |
| 页面数量 | 不新增模板详情页、提交确认页或成功页 |

C11单页主体逻辑已经确认。仍需等待C02／C03统一产品与器械组配方案后，回补模板卡片紧凑摘要、轻量详情完整需求和候选需求组的最终表达；该回补口不改变C11页面身份、两层结构、保存提交或返回关系，也不授权开始低保真。
