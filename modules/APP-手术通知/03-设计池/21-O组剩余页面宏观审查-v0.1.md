# O组剩余页面宏观审查 v0.1

> 状态：宏观方案已确认；O04单页逻辑已于后续收口
> 确认日期：2026-08-19
> 范围：在O01已经成为正式订单总承载页后，重新判断O03与O04的独立页面身份；不制作低保真，不展开Web后台、库存、手术植入或S01内部设计。

## 1. 继承事实

- O01是订单生成后的唯一总承载页面，展示当前任务、订单身份与主状态、主订单与接续订单、整单或分批交付、本单物品结果及当前可执行操作；
- 普通整单和普通分批的供货、出货、照片、清单、预计或实际到手及本人接收事实均由O01按对应批次展示；
- T02以一次真实交付批次为业务对象，承载本人核对与确认接收；同一批次可以关联本人多张订单，结果分别回写各来源O01；
- T03只承载确认接收前的现场异常；
- O01只展示当前有效事实，不堆叠完整版本时间线；
- 已结束、撤回或替代的T01事项需要从订单正式记录进入只读上下文；
- 面向业务员统一使用“发货与接收”，不使用“履约与交付”作为页面名称。

## 2. O组整组职责

O组负责正式订单的两类问题：

1. **现在是什么**：由O01回答当前任务、当前订单内容、当前交付事实、当前物品结果和当前动作；
2. **过去发生过什么**：由O04回答与业务员有关的完整正式订单事实及其可追溯来源。

O组不重复承担真实交付确认、收货异常、变更取消、还回办理或其他任务页的正式动作。

## 3. 能力—现有承载位置矩阵

| 业务能力 | 当前承载位置 | 是否需要O03独立页面 |
|---|---|---|
| 查看本订单已发、待发及当前接收事实 | O01发货与接收区 | 否 |
| 查看整单或分批照片、清单、预计／实际到手信息 | O01对应批次展开 | 否 |
| 核对并确认一次真实交付批次 | T02 | 否 |
| 处理同一真实交付批次关联本人多张订单 | T02统一核对，各来源O01分别回写 | 否 |
| 申报确认接收前的现场异常 | T03 | 否 |
| 查看复杂批次的完整清单、照片或证据 | O01中的只读批次详情、抽屉或展开组件 | 否；信息复杂度本身不成立正式页面 |
| 查看订单当前有效结果 | O01对应业务对象 | 否 |
| 查看提交、受理、变更、协同、交付、接收、手术结果、物品去向、异常及完成等正式历史 | O04订单记录 | 是，保留O04 |
| 查看已结束事项的原始业务上下文 | O04定位记录，再进入对应T／S页面只读状态 | 是，O04承担统一历史入口 |

## 4. 候选页面处置

| 候选页面 | 处置 | 宏观结论 |
|---|---|---|
| O03 供货与收货详情 | 删除独立页面身份 | 订单维度事实已由O01承载，当前批次动作已由T02承载；复杂只读查看改为O01批次轻量下钻，不再计正式页面 |
| O04 订单记录 | 保留并收窄 | 只承载正式历史事实、版本与结果追溯，以及已结束事项的只读入口；不成为第二张订单详情 |

## 5. 删除反证

### 5.1 O03删除结论

删除O03后没有产生无法承接的本人动作、进入条件、返回或结果回写：

- 当前订单交付事实留在O01；
- 当前实际交付确认进入T02；
- 接收前异常进入T03；
- 复杂只读内容由O01具体批次的渐进展开承载；
- 正式历史结果进入O04。

O03没有独立本人动作，也没有O01或T02无法承载的稳定业务上下文，因此不满足独立页面成立条件。

### 5.2 O04保留反证

若删除O04，首次提交、撤回重提、版本替代、补充单取消、已结束协同、接收确认、异常、追回、入库／转用、还回、重新打开及最终完成等正式历史只能堆回O01。这样会把“当前有效事实”和“历史演进”混在同一总承载页，并使已结束T01等事项失去统一只读入口。

因此O04具备独立业务上下文、稳定入口、清晰返回和必要结果追溯职责，删除反证不成立，保留为独立页面。

## 6. O04宏观边界

O04应当：

- 按时间保存与业务员有关的正式业务事件；
- 表达事件时间、正式事项、结果及必要影响；
- 必要时进入对应T01、T02、T03、T05或S01的只读业务上下文；
- 从O01末端“查看订单记录”进入，返回时恢复O01原位置。

O04不得：

- 重复O01中的医院、术者、完整当前需求和当前交付清单；
- 复制T01自由沟通全文；
- 保存后台内部操作日志或不影响业务员结果的系统噪声；
- 提供改变当前订单的正式动作。

### 6.1 已确认的单页业务身份

O04与来源O01一一对应，绑定同一台手术需求组。主订单和全部接续订单共同进入同一O04，但每条正式记录仍标明自身所属对象。复制需求新建形成新的O01与O04；跨订单共同交付批次只记录对当前手术需求组的正式影响，不复制其他订单历史。
