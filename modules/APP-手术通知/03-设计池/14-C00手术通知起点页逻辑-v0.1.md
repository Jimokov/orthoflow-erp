# C00 手术通知起点页逻辑 v0.1

> 状态：单页逻辑已确认
> 更新日期：2026-08-18
> 范围：只定义C00单页逻辑；不制作低保真，不展开C02、C10、C11内部结构

## 1. 页面身份

C00是手术通知的稳定创建起点，用来回答“这次从哪里开始，或者继续哪一笔未完成需求”。它不是草稿中心、订单中心、模板中心或业务工作台。

G01“手术通知”固定进入C00。系统可以根据当前是否存在订单草稿改变C00展示的内容，但不得据此把同一个G01入口有时导向C00、有时直接导向C02。

## 2. 导航外壳

- C00是G01下的二级页面，顶部显示返回按钮和“手术通知”标题；
- C00顶部返回G01，并恢复进入前的首页现场；
- C00不显示首页、订单中心、我的组成的全局底部导航；
- C02、C03、C09、C10、C11同属创建域二级／内部页面，均不重复显示全局底栏；

### 2.1 返回来源矩阵

编辑链记住本次进入来源，不把所有返回统一导向C00：

| 进入路径 | 编辑链退出目标 | 现场恢复 |
|---|---|---|
| C00空白新建 → C02 | C00 | 刷新草稿条件区；无实际输入时不产生草稿 |
| C00最近草稿 → 上次有效编辑页 | C00 | 已保存内容更新后刷新最近草稿 |
| C00 → C10 | C00 | 恢复C00进入前状态 |
| C10选择草稿 → 上次有效编辑页 | C10 | 恢复原列表位置 |
| C00 → C11，未使用模板 | C00 | 恢复C00进入前状态 |
| C11使用模板形成订单草稿 → C02 | C00 | 模板选择使命已经完成，不退回C11重复选择 |

C03、C09是编辑链内部页面：内部返回先回C02相应位置；只有退出C02编辑中枢时，才按上表回到本次来源页。以上矩阵只处理订单草稿路径，不提前规定C11模板候选编辑态的返回规则。

退出前有实际输入时先完成自动保存；没有实际输入的空白新建直接返回C00，不形成可见草稿。

## 3. 已确认的首屏分流

### 3.1 始终显示

- **空白新建**：主要操作，进入C02统一需求编辑中枢；
- **从模板创建**：次级入口，进入C11需求模板。

即使当前没有草稿，两种真实创建方式仍同时存在，因此C00不是“只有一个新建按钮的空页面”。

### 3.2 有订单草稿时条件显示

- 展示“继续未完成”区域；
- 只在C00呈现最近一张草稿；
- 提供进入C10“全部草稿”的入口。

最近草稿卡片只呈现继续辨认所必需的信息，并按当前填写进度渐进显示：

- 医院和术者已经填写一项或两项时，以现有信息组成主标题，不为缺失项单独占行；
- 手术日期已经填写时显示，未填写时不生成“日期待填写”占位；
- 医院、术者和手术日期三项均未填写时，主标题统一为“新建需求（信息未完善）”；
- 信息尚不完整时只使用一个低强调的“信息未完善”标识，不逐项罗列缺失字段；
- 草稿类型和最后编辑时间始终显示；
- 补充或撤回修改草稿额外显示关联订单号，普通新建草稿不占用这一行。

整张草稿卡片点击后恢复到上次有效编辑页，不再另设语义重复的“继续”按钮。删除和其他草稿管理动作不进入C00，统一留在C10“全部草稿”。

### 3.3 草稿形成与最近排序

- 点击“空白新建”并进入C02本身不生成一张可见草稿；
- 用户首次产生实际输入且本机持久保存成功后，该内容才进入C00和C10的订单草稿集合；
- 模板、复制需求、补充和撤回修改等入口已经带入有效内容，本机持久保存成功后可以直接形成可见草稿；
- 多张可见草稿按内容最后一次成功保存在本机的编辑时间倒序排列，第一张作为C00“最近草稿”；
- 不按草稿创建时间、手术日期或网络恢复后的公司端同步时间决定最近顺序；尚未同步的草稿仍可显示，并使用低强调的“待同步”标识。

### 3.4 失效或无权限草稿

- C00的最近草稿只从当前仍可继续编辑的草稿中选择；
- 补充或撤回修改草稿因来源订单状态、权限变化而不能继续时，不占用最近草稿卡片，也不能被系统静默删除；
- 同时存在可继续草稿时，C00正常展示最近一张可继续草稿，失效草稿只留在C10处理；
- 没有可继续草稿但仍有失效草稿时，不显示最近草稿卡片，只保留一条低强调入口“有草稿无法继续，查看全部草稿”，进入C10；
- 具体失效原因、内容保留和删除方式归C10单页逻辑，不在C00提前设计。

### 3.5 没有订单草稿时

- 整个“继续未完成”区域隐藏，不显示空卡片、零数量或占位提示；
- 页面只保留“空白新建”和“从模板创建”；
- 不为填补留白加入正式订单、任务、统计、教程、最近记录、常用模板或首页式看板；
- 允许页面保持克制留白，信息密度不作为增加职责的理由。

## 4. 稳定入口原则

不采用“无草稿时G01直达C02”的条件路由，原因是：

1. 同一入口不应因用户不可见的草稿状态改变落点；
2. 直接进入C02会削弱或迫使迁移“从模板创建”的自然入口；
3. 首次进入、产生草稿后再次进入及页面返回会形成不一致路径；
4. 节省一次点击不足以抵消入口不可预测和G01／C02职责膨胀。

因此当前固定关系为：

```text
G01 手术通知
└─ C00 手术通知起点页
   ├─ 空白新建 → C02
   ├─ 从模板创建 → C11
   └─ 继续未完成（仅有草稿时）
      ├─ 最近草稿 → 上次有效编辑页
      └─ 全部草稿 → C10
```

## 5. 明确边界

- C00不展示正式订单、订单状态、履约、待我处理或订单操作；
- 复制需求新建、撤回修改和补充仍从来源O01进入，不增加为C00入口；
- C00不展开模板集合、下载、候选申请或审核结果，这些内容由C11承载；
- 未来“植入取出”只保留跨模块创建来源接口，当前不显示不可用入口，也不能用它填充C00。

## 6. 单页收口检查

| 检查项 | 结论 |
|---|---|
| 页面身份 | C00只负责开始或继续需求，职责单一 |
| 稳定入口 | G01固定进入C00，不以草稿状态改变路由 |
| 首屏动作 | 空白新建为主、从模板创建为次，职责闭合 |
| 草稿状态 | 无草稿、有效草稿、仅失效草稿三类状态均有明确呈现 |
| 草稿形成 | 空壳不入集合，实际输入在本机持久保存成功后形成可见草稿；公司端同步不阻塞显示 |
| 最近草稿 | 信息、排序、整卡继续和不完整信息识别均已明确 |
| 权限变化 | 失效草稿不冒充可继续项、不静默删除，进入C10处理 |
| 导航与返回 | 二级导航、无全局底栏及来源返回矩阵已经闭合 |
| 页面边界 | 订单、任务、模板集合、全部草稿管理和未来功能未被塞入C00 |

检查结论：未发现需要继续业务确认的C00阻塞缺口。加载、网络失败、骨架屏和无障碍等通用表现留到低保真／交互验收按既有规则落实，不新增业务能力。2026-08-18用户已确认C00整体收口，本页升级为“单页逻辑已确认”。
