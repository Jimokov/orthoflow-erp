# 手术通知 APP 总池

> 建池日期：2026-08-10  
> 当前阶段：页面设计  
> 当前作用：这是任何新任务接管“手术通知 APP”的唯一入口。

## 1. 模块身份与边界

- 所属端：业务员移动端 APP；
- 模块核心：业务员围绕确定手术时间向公司提出产品和器械缺口需求，并承接后续订单协同、实际交付确认及本单物品结余；
- 本模块不是字面意义上的手术排程通知；
- 业务员已有并可直接用于销售的本人库存不进入本次缺口要货；
- APP 不向业务员展开公司内部采购、借用、调拨和仓库来源判断；
- 手术植入、库存、消毒及 Web 后台保持独立模块，本池只保存已经确认的衔接结果，不代替它们定义内部流程。

## 4. 当前必须继承的关键结论

- 底部全局入口是首页、订单中心、我的；
- 手术通知模块通过自己的工作区承接新建和草稿，草稿不放在全局首页或订单中心；
- 订单中心只聚合正式订单，分当前订单和历史订单；
- 订单主状态使用待受理、处理中、待发货、已发货、待结余、已完成、已取消；
- “待还回”不是订单主状态，还回是待结余下的一条物品去向分支；
- O01 展示订单主状态、关键结果和当前需要业务员处理的动态任务；
- T01 是绑定订单的“订单协同”，不是让业务员逐项回答后台预设的是非题；
- T03 只能从实际交付确认 T02 中进入；
- 手术植入只带入本次实际需要的部分物品，不默认全选；
- 植入结果先回写 O01，仍有物品未落实去向时才进入“本单物品结余”；
- 现有低保真仍含旧状态词和旧 T 页面表达，不能作为当前规则依据。
