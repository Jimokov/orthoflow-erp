# 手术通知跨模块发现待论证清单 v0.1

> 身份：当前有效的通知模块论证入口清单；不新增或修改手术通知规则、接口、页面、任务或状态。
>
> 用途：其他模块发现手术通知可能存在未论证边界时，先在此登记，再由手术通知对话自行论证、确认或拒绝。

## 1. 使用规则

- 只登记可能影响手术通知自身对象、责任、结果、任务、接口、术语或页面承载的问题；
- 每条发现必须引用发现方的当前资料和手术通知已知资料，不能以旧聊天或候选想法替代依据；
- “可能影响”不是手术通知事实，也不授权发现方修改通知资料；
- 手术通知对话处理后，先更新通知拥有的正式事实资料，再把本条标为已确认并链接去向、已拒绝或继续保留桩子；
- 只有已确认的交叉事实或稳定桩子才同步至项目级跨模块遗产索引。

## 2. 条目模板

| 字段 | 必填内容 |
|---|---|
| 编号与状态 | `N-Xxx`；待手术通知论证／已确认并已转入／已拒绝／保留桩子 |
| 发现来源 | 发现模块、触发场景和当前资料位置 |
| 已知通知事实 | 当前通知资料已经覆盖的内容及来源 |
| 待论证问题 | 一个明确的通知模块问题，不预写答案 |
| 可能影响 | 可能涉及的通知资料或相邻模块结果 |
| 处理与退出 | 后续由谁论证；确认后写入的正式资料位置或拒绝理由 |

| 已知通知事实 | 当前规则 §10.3 规定业务员确认接收时不需要逐件扫码，后台已冻结产品、规格、批号、序列号和数量；通知只将已实际接收、仍绑定需求组的候选实物带入植入。 |
| 收口结论 | 不增加逐件扫码，也不把“一码一物”设为手术通知前提。业务员确认正常接收后，系统按冻结出货清单明细形成可回查的本人接收交接事实，关联实际交付批次、来源需求组或订单、接收人、确认时间、产品、规格、批号／可追溯身份（如有）及正常确认数量。 |
| 交叉边界 | 植入侧以胶贴或同等凭证的产品、批号／可追溯身份与数量回查该交接；无法形成正常来源归属时，不得人工改归通知来源，按“来源核验异常”处理。相同批号经多次有效交接后的细分分摊不在本条展开。 |

### N-X02｜已收口（2026-09-04）

| 字段 | 内容 |
|---|---|
| 发现来源 | T1 手术植入的来源核验异常及从通知任务进入场景，[实物销售来源与通知回写 v0.3](../../APP-手术植入/01-规则池/06-手术植入APP实物销售来源与通知回写-v0.3.md) §1.1、[来源锚定推演记录](../../APP-手术植入/04-业务闭环/11-植入物来源锚定推演记录-v0.1.md) §8。 |
| 已知通知事实 | 通知只有收到正式植入结果中的通知来源明细后才重算责任与结余；实际接收数量须由实际植入、还回、批准转用、批准异常处置及在手待结余等去向守恒；订单完成须形成有效植入结果或取消结果，并且全部已接收实物已落实最终去向。 |
| 收口结论 | 对携带来源手术通知或需求组上下文的正式植入来源核验异常，通知接收非结清的“来源待核实使用关联”，将相关数量记为“已使用，来源待核实”。它不是正常通知来源植入、批准异常处置或在手待结余；归入O01既有“异常处理中”结果，不新增订单主状态或独立页面。 |
| 数量与完成 | 数量守恒新增“已使用、来源待核实数量”临时项。它不为零时订单不能完成；手术情况确认任务可随正式植入结果结束，除非公司确实需要补充事实或凭证，不自动生成本人待办。 |
| 后续校正 | 真实上游链核实为本通知来源时，转换为正常通知来源植入；核实为其他来源时，撤销待核实关联，通知候选实物恢复原责任；始终无法核实则继续阻止订单完成。无通知上下文的来源核验异常不得触碰任何O01。 |

### N-X03｜已收口（2026-09-04）

| 字段 | 内容 |
|---|---|
| 发现来源 | T1 手术植入对正式结果生命周期的反向核查，[双向结果接口 v0.3](../../APP-手术植入/02-接口池/01-手术通知双向结果接口-v0.3.md) 与 [取消／失效反向回写链路 v0.2](../../APP-手术植入/04-业务闭环/05-取消失效反向回写链路-v0.2.md)。 |
| 已知通知事实 | N-X02 已确认“来源待核实使用关联”会使通知记录“已使用，来源待核实”、阻止订单完成，并可在来源核实后转换或撤销。当前通知接口摘要的取消／失效与销错冲正段只明确原正常通知来源分配的反向调整。 |
| 收口结论 | 原正式植入记录被取消、失效或销错冲正时，通知按原记录关系撤销其一切通知侧结果：正常来源植入数量、仍有效的来源待核实使用关联及其已转换出的正常来源结果。撤销后候选实物恢复应有责任，并按剩余有效记录重算数量、待结余与完成资格；销错冲正先完整撤销原记录，再由正确的新正式记录独立形成新结果。 |
| 边界与任务 | 来源核实只是同一有效记录内的责任校正，不属于取消。原记录撤销后，若无有效植入、已生效延期或已生效取消结果且当前有效计划时间已过，则按既有条件重新生成手术情况确认任务；否则不自动生成本人待办。O01承载当前重算结果，O04保留可追溯调整链，不新增页面或订单状态。 |
