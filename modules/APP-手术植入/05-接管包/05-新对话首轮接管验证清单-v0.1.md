# 新对话首轮接管验证清单 v0.1

> 身份：新对话接管前的核验清单，不是业务规则。

## 1. 启动前核验

- [ ] 运行锁定项目 Skill 的 `verify_snapshot.py`，失败即停止。
- [ ] 读取根 `AGENTS.md`、`docs/governance/Skill版本锁定.md`、范围登记、植入 `00-START-HERE.md`、路线图、规则基线和接口登记。
- [ ] 涉及通知时读取通知当前有效跨模块接口摘要与 `CONTEXT.md`；不读取通知旧聊天或旧稿。
- [ ] 从当日日报“对话编号断点”续接正式回复编号。
- [ ] 核验本接管包 C-01—C-05；有停止项时明确影响范围。

## 2. 首轮只验证的重点

1. **正式资料一致性**：R-04 的来源边界表述是否已与 R-06 对齐；未对齐则先修复，不开启 R-11—R-13。
2. **患者、病例与凭证的资料身份**：区分 R-02／R-03 已确认基础信息、当前主对话已确认但未正式化的病例／凭证方案，以及 P-01／P-04 后台桩子。
3. **通知接口边界**：只使用 O01／G03 → 植入 → 正式结果回写的既有契约，不新增入口、页面或库存能力。

## 3. 首轮不可做的事项

- [ ] 不把旧对话或本接管包的历史表述升格为事实。
- [ ] 不设计 APP／Web 页面、低保真、库存算法、后台患者管理或提成方案。
- [ ] 不在 R-11—R-13 之外扩展生命周期、销错或结算规则。

## 4. 首轮完成标准

- [ ] C-01 已处理，或被正式登记为阻塞并停止相关判断；
- [ ] 本轮唯一待决问题、已核实依据、推荐与直接影响均已记录；
- [ ] 有效结论只写入对应规则池／接口池／总池及适用进度资料。
