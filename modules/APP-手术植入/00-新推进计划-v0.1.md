# 手术植入模块新推进计划 v0.1

> 身份：已于 2026-08-27 经用户确认的推进控制计划；不新增或修改业务规则、接口、正式页面或实现规格。
>
> 依据：已确认的《推进方向调整可行性论证 v0.1》与《继承基线全量检查记录 v0.1》。

## 1. 推进总方向

后续不再以旧 P 阶段或 R 编号作为日常进入方式，而围绕一条可直接理解的完整业务流程推进：

```text
现实手术完成
→ 从 G01 独立进入，或从手术通知的手术情况确认进入
→ 建立本次实际手术事件和植入记录
→ 登记实际销售明细及其来源
→ 关联凭证、提交并经自动校验
→ 形成正式结果
→ 仅通知来源明细回写手术通知
→ 必要时处理未正式恢复、取消／失效或销错冲正
```

这条流程及其既有规则、接口和探索成果全部继承；本计划不要求重做流程，也不把低保真升级为正式页面或实现。

## 2. 工作组织原则

- **流程是讨论主线**：每次从流程中的真实业务问题进入，用业务语言说明角色、动作、结果和返回；旧编号只留作资料定位。
- **资料是事实依据**：已有结论直接继承；由资料可直接得到的内容标为推导；会改变责任、状态、正式结果、跨模块回写或模块边界的事项才作为待确认问题。
- **探索是验证载体**：完整闭环探索图和低保真继续用于走通场景、暴露问题；其样例、按钮和状态不会自动成为规则、页面或代码。
- **桩子按流程暴露和处理**：只在实际影响当前流程理解或下一步验证时讨论，不为文档完整性提前补齐。

## 4. 第一项任务

计划确认后，第一项任务是 **A. 完整流程情景推演**。

它的目的不是重新论证“手术植入是否存在这条流程”，而是把已继承的流程用连续、可理解的业务场景走一遍，让每个正式结果、通知回写和真实桩子都能被看见。任何已确认内容不重问；任何无法从资料得到、且会改变业务的内容，才暂停并明确提出。

## 5. 执行硬边界与停止条件

- 旧 P0—P8、P2 及 R-11—R-19 的旧范围记录永久退出日常执行入口，只作追溯；
- 不读取旧聊天补事实；历史接管包只核验身份与来源；
- 不进入库存、Web 后台、视觉、代码、销售汇总或提成；
- 未闭合的权限、时限、审核、字段、算法、幂等、重试、数据销售边界等继续是桩子，不能由流程或原型静默补齐；
- 发现资料冲突、接口缺口或需要聊天记忆时，暂停受影响流程段，记录缺口、影响、正式资料位置和恢复条件；其他不受影响段可继续。

## 6. 已确认与替代关系
