## 1. 本组业务目标

让业务员在一次真实手术完成后，建立一条实际手术事件记录，登记实际销售明细及其来源，提交凭证并获得正式结果；只有正式结果中的通知来源明细才回写手术通知。页面只承载 APP 业务员动作，不承载库存内部作业、Web 后台、医患管理或销售结算。

## 2. 核心对象与正式结果

| 对象 | 页面需要承载的事实 | 正式结果 |
|---|---|---|
| 实际手术事件 | 患者、基础信息及动作事实 | 一次事件与植入销售记录的绑定 |
| 植入销售记录 | 业务员、患者、事件、销售形态快照 | 自动校验通过后形成正式植入记录 |
| 实际销售明细 | 产品、数量、批号／追溯身份、来源 | 只有明细进入正式销售结果 |
| 通知来源候选实物 | 已接收、仍绑定的候选实物 | 被实际植入部分回写，未植入部分保留原责任 |
| 凭证 | 已上传／已关联的证据 | 供提交校验；具体字段仍为桩子 |

## 3. 业务能力—页面承载矩阵

| 业务能力 | 资料性质 | 建议承载位置 | 是否独立页面 | 说明 |
|---|---|---|---|---|
| G01 独立进入 | 已确认事实 | 外部入口 → I01 | 否 | G01 只负责进入，不复制植入记录流程 |
| O01／G03 任务进入 | 已确认事实 | 外部任务入口 → I01 | 否 | 携带需求组、任务、返回位置和候选实物 |
| 建立实际手术事件 | 已确认事实 | I01 顶部／基础信息区 | 是（I01） | 形成记录上下文的独立业务动作 |
| 患者与基础信息 | 已确认事实 | I01 基础信息区 | 否 | 不创建独立患者管理页 |
| 实际手术动作事实 | 已确认规则＋待定承载方式 | I01 条件区块 | 否 | 动作不自动形成销售结果；字段与录入时点不在本轮补全 |
| 添加实际销售明细 | 已确认事实 | I01「实际销售明细」区块／编辑组件 | 否 | 扫码与手动添加形成同一明细 |
| 自有库／通知来源分配 | 已确认事实 | I01 明细行来源分配组件 | 否 | 支持混合来源；不画库存内部流程 |
| 凭证关联 | 已确认链路 | I01 提交前凭证区块 | 否 | 只表达留存与关联，不补字段或后台审核 |
| 自动校验与提交 | 已确认链路 | I01 提交动作＋结果状态区块 | 否 | 通过／异常状态先作承载占位 |
| 正式结果与通知回写 | 已确认接口 | I01 结果状态区块＋返回原入口 | 否 | 仅正式结果触发回写 |
| 未正式形成、补齐重提、放弃／超期退出 | 已确认方向 | I01 状态区块 | 否 | 具体时限、权限、提醒保持桩子 |
| 取消／失效／修改／冲正 | 已确认方向＋细节桩子 | I01 正式记录条件操作区块 | 否 | 不新建生命周期页面；具体权限与审批待后续确认 |

## 4. 第一版建议页面集合

### I01 手术植入记录（独立页面）

这是当前唯一具备独立业务上下文、稳定进入条件、明确本人动作、清晰结果回写的页面候选。它承载一次实际手术事件从建立到正式结果／未正式退出的完整工作区。

建议区块：

- 来源与返回上下文：G01 或 O01／G03；通知入口携带的需求组和候选实物只作为上下文；
- 手术事件与基础信息：患者、医院、科室、术者、住院号等已确认边界；
- 实际手术动作：作为事件事实占位，不从动作名称推导销售；
- 实际销售明细：扫码／手动添加、数量和追溯信息；
- 来源分配：自有库、通知来源或混合来源；
- 凭证与提交：凭证关联、提交和自动校验入口；
- 结果状态：正式结果、未正式形成、异常／待审核、补齐重提、退出及通知回写占位。

## 5. 候选页删除反证

| 候选页 | 处置 | 删除反证检查 |
|---|---|---|
| P02 实际销售明细页 | 删除，作为 I01 条件区块／编辑组件 | 删除后，明细添加、扫码／手动和来源分配仍可由 I01 清楚承载；没有独立返回或跨对象结果 |
| P03 提交／校验页 | 删除，作为 I01 提交与结果区块 | 删除后，提交、校验和异常占位仍属于同一记录；没有独立业务对象 |
| P04 正式结果页 | 删除，作为 I01 结果状态 | 正式结果是 I01 的结果，不新增本人业务动作；通知回写由接口完成 |
| P05 待完成／失败恢复页 | 删除，作为 I01 状态与条件动作 | 补齐重提、放弃／超期退出都围绕同一未正式记录；具体时限和权限尚未足以成立独立上下文 |
| P06 取消／冲正页 | 暂不成立，保留条件区块桩子 | 触发、权限、审批和失败恢复尚未封闭；不能用独立页替代规则确认 |

## 6. 入口、返回与结果回写关系

```text
G01 ───────────────┐
                   ├─→ I01 手术植入记录
O01／G03 记录手术植入 ┘       │
                              ├─ 未正式形成：留在 I01，补齐重提或退出；不回写
                              ├─ 校验异常：进入异常／审核占位；不回写
                              └─ 正式形成：输出记录引用及通知来源明细
                                      └─ 返回原通知任务／目标，通知重算责任与结余
```

## 7. 分类与边界

- 已确认事实：直接进入 I01 的结构和交互承载；
- 推导结果：将同一记录的明细、提交、结果与恢复放在 I01 的条件区块中，以避免无独立职责的页面；该结论是承载推导，不是新增业务规则；
- 真实待决：具体状态名称、权限、时限、凭证字段、异常审核反馈、通知回写幂等，只以占位／桩子呈现，不静默补全。

## 8. 宏观审查结论

当前第一版建议页面集合为单一独立页面 I01，辅以明细编辑、来源分配、凭证、提交／结果和恢复条件区块。该集合覆盖主流程和必要异常，不建立重复的明细、结果或生命周期页面。用户确认本宏观方案后，才进入 I01 的低保真探索稿；该探索稿不等于模块设计验收通过。

全局页面总览与 I 组总览属于原型审阅导航层，不计入手术植入正式业务页面；其风格和导航关系沿用原始低保真原型。
