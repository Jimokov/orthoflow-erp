# 手术植入完整闭环探索承载图 v0.1

> 状态：已按 v0.2 完成复核的历史低保真探索承载稿；来源人工选择等旧表现不得直接继承。不是正式页面清单、设计验收或实现规格。  
> 建立日期：2026-08-25  
> 依据：当前规则基线、接口登记、业务主线、实物销售全流程逻辑验收与总路线图 v0.2 及手术通知跨模块接口摘要。

## 1. 整组判断

当前探索目标不再比较 I01 的静态排版，而是验证一条植入销售记录能否从入口、形成、来源分配、提交校验、正式结果，到取消／失效／纠正和通知回写完整走通。

I01—I05 是同一业务对象的**低保真探索节点**，不是已经确认的五张正式业务页面。后续设计验收前，仍需按页面身份、删除反证和业务闭环规则重新确认。

## 2. 探索节点与承载关系

| 节点 | 当前对象与角色 | 本人动作 | 结果／下一节点 | 返回与边界 |
|---|---|---|---|---|
| 全局页面总览 | 原型审阅者 | 选择 I 组 | 进入 I 组总览 | 审阅导航，不是业务员 APP 页面 |
| I 组总览 | 业务员的植入业务链路 | 选择入口场景与探索节点 | G01／O01／G03 → I01 | 只说明主线、边界和回写 |
| I01 建立事件／患者基础信息 | 一次实际手术事件、植入销售记录 | 建立本次事件、录入已确认基础信息、记录动作事实 | I02 | 动作事实不自动形成销售结果 |
| I02 添加实际销售明细 | 植入销售记录、实际销售明细 | 扫码或手动添加同一种明细 | I03 | 产品、批号／追溯身份（如有）、数量只作已确认边界展示 |
| I03 产品来源分配 | 销售明细、来源分配、通知候选实物 | 选择业务员侧常备物资、通知来源或混合来源 | I04 | 不展示库存可用量，不建立库存内部动作 |
| I04 凭证关联与提交前确认 | 植入记录、凭证 | 关联凭证、提交并触发自动校验 | I05 | 凭证字段、审核角色和时限均为桩子 |
| I05 自动校验与正式结果 | 已提交植入记录、正式记录引用 | 查看通过／异常／未完成；补齐重提、退出或进入正式结果后续分支 | 回原入口、取消／失效、冲正纠正 | 只有正式结果的通知来源明细触发回写 |

## 3. 可点击闭环

```text
全局总览 → I 组总览
  ├─ G01 独立进入 ───────────────┐
  └─ O01／G03「记录手术植入」 ───┤
                                  ↓
                         I01 → I02 → I03 → I04 → I05
                                                   ├─ 未完成／异常 → 补齐后回 I01／I04 → 重提
                                                   ├─ 正式结果 → 通知来源正向回写 → 返回 O01／G03 或 G01
                                                   ├─ 取消／失效 → 保留原记录 → 通知来源反向回写
                                                   └─ 销错冲正 → 保留原记录 → 反向回写 → 正确结果重走 I02—I05
```

## 4. 状态与回写

| 分支 | 正式结果 | 手术通知回写 | 恢复 |
|---|---|---|---|
| 未完成／补齐中 | 否 | 不回写 | 回到相应节点补齐并重提 |
| 自动校验异常 | 否 | 不回写 | 异常占位；补齐后重提，审核细节为桩子 |
| 自动校验通过 | 是 | 仅通知来源明细正向回写；业务员侧常备物资不回写 | 返回来源入口 |
| 取消／失效 | 原记录保留 | 仅原通知来源明细反向回写 | 触发、权限、时限和幂等为桩子 |
| 修改／销错冲正 | 原记录与错误明细保留，正确结果另行形成 | 通知来源先反向，再以正确结果正向回写 | 重新进入 I02—I05 形成正确结果 |

## 5. 不进入范围

- 不把 I01—I05 固化为正式页面数量；
- 不补写库存可用量、扣减、入库、调拨或库存恢复；
- 不补写审核岗位、权限、时限、算法、回写幂等和后台流程；
- 不进入 Web 后台、视觉稿、代码实现、销售汇总或提成。
