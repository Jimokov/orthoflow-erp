### 协作能力辅助建设路线

该路线由 T1 提供第一组真实应用和失败证据，但不属于手术植入业务能力，也不得取代任何 `Tn` 的成果任务。成熟后的通用能力应独立于杏林骨科；杏林只保留项目应用状态、业务证据和测试结果。

| 顺序 | 建设能力 | 当前状态 |
|---|---|---|
| 1 | 用 I01 小型治理任务试运行最小 harness | 已完成首次试运行并通过用户验收；控制面仍在收尾 |
| 2 | 从真实试运行形成第一组 Evals | 当前进入；`Eval-001` 尚未形成 |
| 3 | 建立关键行动的可观察记录 | 已建立首个最小行动记录，随本切片继续验证 |
| 4 | 把写入、发布、跨任务和外部操作变成机械权限 | 未启动，不因前项登记而自动开启 |
| 5 | 整理正式知识入口和失效传播；因果航迹作为上下文治理中独立可见的核心组件 | 因果航迹首例已记录；本项整体尚未启动 |
| 6 | 引入独立审查与角色编排 | 未启动；当前不得假装已经存在独立审查者 |
| 7 | 根据实际效果决定哪些能力进入长期项目底座 | 未启动；不得预设最终工具数量或结构 |

辅助分支只允许一层。当前辅助分支不得再自动开启第二层治理；直接阻塞时只做最小修复，不阻塞的问题登记后返回当前动作。完整运行契约和证据见手术植入模块的[I01 撤销记录](modules/APP-手术植入/06-决策与历史池/02-I01错误权重与低保真准入撤销记录-v0.1.md)。

## 全局门禁与跨任务条件

| 条件 | 当前处理 |
|---|---|
| APP 与 Web 边界 | 未启动的 Web 后台不因 APP 资料自动产生规则、页面或能力；APP 全链路联调暂不启动。 |
| 库存与相邻模块 | T2 若影响手术通知／手术植入的责任或回写，先对齐已确认接口，不在库存任务中补写相邻模块事实。 |
| 公司库存业务域与端模块 | T4 先形成可确认的公司库存业务结果；T2 和未来库存 Web 后台只在其各自任务中承接，不自动产生端能力。 |
| 手术通知 G 组恢复 | T3 的组配方案与核心模块接口条件未满足前，不进入 G 组单页逻辑。 |
| 资料归档与环境恢复 | 任何批量复制、归档、恢复、迁移、跨仓库同步或可能覆盖的操作，先通过[资料财产保护与可回退推进总则](docs/governance/项目资料财产保护与可回退推进总则-v0.1.md)；主仓库仍是唯一当前事实源。 |
