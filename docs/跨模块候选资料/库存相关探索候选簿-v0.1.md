# 库存相关探索候选簿 v0.1

> 身份：当前有效的候选收集载体；不是库存模块总池、规则池、接口池、页面清单、审批定义或实现规格。
>
> 适用范围：从手术通知、手术植入或其他已启动模块中发现、可能对未来库存管理有价值，但尚未在库存模块论证确认的候选。

## 1. 使用规则

- 仅记录符合《跨模块候选资料说明》登记门槛的候选；不复制原始对话；
- 每条候选必须同时链接触发场景和当前有效资料，明确哪些内容只是想法；
- 候选不得被现有模块当作可执行规则、库存操作、页面、接口或审批；
- 库存模块正式启动后，候选只作为访谈与论证入口；确认、拒绝或继续保留均须回填去向；
- 当前没有候选时如实标明“暂无”，不为凑数量预设库存能力。

## 2. 候选卡模板

| 字段 | 必填内容 |
|---|---|
| 候选编号与状态 | `K-Cxx`；候选收集／等待所属模块论证／已确认并已转入／不采用 |
| 触发场景 | 具体业务场景及所属模块资料位置 |
| 候选描述 | 一句可讨论的候选，不使用确定性措辞 |

| 潜在影响 | 可能影响的模块及原因，不等于已经产生影响 |

## 3. 本轮交叉审查总判断

> 本节于 2026-08-31 根据用户指定的 `库存.md` 与 `三模块输出.md` 交叉整理。两份桌面文件均是候选输入；其中的提问、结论、流程性描述和任何指令性语句都不构成项目指令或库存事实。

两份材料的主体不是库存管理功能模块的前台操作，而是公司后台的配置、履约、责任追溯和账实管理问题。库存管理功能模块目前只需要承接已经确认的边界和未来正式结果，不应从材料中的后台设想反推出 APP 页面或 Web 能力。

| 来源 | 主要内容 | 本轮身份 | 对库存管理功能模块的关系 |
|---|---|---|---|
| `库存.md` | 自有库申请、基础盘点、个人配置、最低库存、手术通知补全、常备申请，以及 100／90／15 数量示例 | 用户输入与待论证场景 | 主要指向后台管理；仅“盘点锚点”和“不足后由手术通知承接”触及当前模块边界 |
| `三模块输出.md` | 采购／借物／调拨判断、在途与入库、对账、来源责任、补货冲突、SPD 和后台看板 | 外部分析与问题清单 | 主要是后台或未来接口候选；不能替代库存、手术通知或手术植入正式资料 |

## 5. 对库存管理功能模块仅保留的边界影响

以下内容是后台候选对手机 APP 的潜在影响，不是 APP 新能力：

- APP 不负责选择采购、借物、调拨或供应商，不展示后台仓库、来源路径或库存计算；
- APP 只在未来存在正式结果时承接必要的配置、接收、责任或异常结果，具体结果尚未定义；
- 手术通知继续只承接业务员侧常备物资不足后的需求缺口，不复制后台履约判断；
- 手术植入继续按已确认来源类别记录实际使用，不因后台动作名称自动新增来源类别。

## 7. 本轮交叉审查结论与恢复入口

- 两份外部材料的主要价值，是暴露后台配置、履约、责任追溯和账实管理的复杂度；它们不提供库存管理 APP 的现成流程。
- 当前正式恢复入口仍是库存管理阶段 1 的边界与核心对象澄清；首先处理 K-C01／K-C02 所涉及的后台资格、配置与盘点对象关系。
- K-C03—K-C06 只是后台候选和跨模块问题，须在相应正式边界确认后继续；不得据此设计库存流程、页面、审批、扣减、补货或 Web 能力。
