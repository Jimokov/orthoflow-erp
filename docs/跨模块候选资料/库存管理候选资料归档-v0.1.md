# 库存管理候选资料归档 v0.1

> 身份：跨模块候选资料归档，不是 `APP-库存管理` 模块总池、规则池、页面清单、接口协议或实现规格。
>
> 建立日期：2026-08-27
> 适用目的：集中保存已经由其他模块正式沉淀、但未来库存管理必须读取的约束、结果、术语差异和桩子；也供现有模块在涉及库存边界时按需调取。
>
> 事实边界：只收录仓库中的当前有效资料及明确标为探索的资料；不读取旧聊天。未沉淀在资料池的“用户或助手曾讨论内容”不能在此被当作事实补入。

## 1. 使用规则

1. 本归档不是库存模块启动授权。库存管理仍处于概念阶段；在用户正式启动前，不据此创建库存流程、页面、代码、后台能力或未确认规则。
2. 标为“已确认外部约束”的内容，可作为其他模块不得违反的边界；它不自动变成库存模块内部的动作、状态或权限。
3. 标为“探索／桩子”的内容只用于定位未来讨论起点，不能被实现、页面或接口静默补全。
4. 日后库存模块正式启动时，先建立其模块总池、启动路线图、当前规则基线和接口登记；本归档作为候选资料输入，由用户逐项确认去向后才可写入库存正式资料。

## 2. 当前项目定位

| 项目 | 当前结论 |
|---|---|
| 库存管理成熟度 | 概念阶段，尚无可封板的完整规则、页面或实现资料 |
| 已允许的沉淀形式 | 跨模块候选资料与明确接口边界 |
| 当前禁止推导 | 库存流程、库存页面、库位／仓库模型、库存扣减、调拨、入库、审批、盘点、采购、退货、质检、后台能力或技术接口 |
| 与手术通知关系 | 只能继承批准入个人仓的结果与可追溯实物责任；不能继承要货、公司履约或订单主状态机 |
| 与手术植入关系 | 只存在实物来源与通知回写边界；植入不承担库存扣减、恢复、入库或个人仓审批 |

## 3. 已确认的库存相关外部约束

### 3.1 手术通知的要货与公司内部库存边界

| 编号 | 已确认外部约束 | 对未来库存的含义 |
|---|---|---|
| K-01 | 业务员只申报本次手术需要公司提供的**缺口**；本人已有且可直接销售的库存不重复进入要货 | 库存若将来提供可用结果，不能反向把已持有实物塞回手术通知需求 |
| K-02 | 手术通知不展示总仓、地方仓、个人仓、当前可用数量、批号、仓库或上游来源 | 库存内部事实可存在，但其前台暴露范围须另行确认，不能由通知页倒推 |
| K-03 | 公司自行决定总仓、地方仓、采购、借调或其他合法来源来解决需求 | 这些是公司内部履约，不是业务员选择的库存动作；未来库存／后台不得把内部路径错误转化为业务员按钮 |
| K-04 | 公司内部来源、仓库和作业变化通常静默；只有影响业务员判断的正式结果才进入订单详情／任务 | 库存变化本身不自动成为订单状态、待办或强提醒 |
| K-05 | 产品需求不选择批号、序列号、仓库或上游来源；器械包资产编号由后台配货时确定 | 未来库存可维护可追溯身份，但其在创建需求阶段的选择权尚未成立 |

### 3.2 实际接收后的责任、入库和转用

| 编号 | 已确认外部约束 | 对未来库存的含义 |
|---|---|---|
| K-06 | 业务员确认接收后，实物先进入来源订单的“在手待结余”，**不会自动**成为个人仓可用库存 | 接收、责任建立和个人仓可用是不同事实；库存不能用接收事件自动入库 |
| K-07 | 转入个人仓是业务员提出的申请，只有后台批准后生效；O01前台结果显示“已入库” | 未来库存至少需要接收“批准入个人仓结果”及可追溯实物责任，但申请、审批和入账细节尚未定义 |
| K-08 | 转入本人其他明确订单同样是申请，后台批准后生效；没有明确目标订单不能转用 | 未来库存／实物流转需要保留来源订单、目标订单、实物身份、数量和批准结果，不能只记笼统移动 |
| K-09 | 严禁跨业务员转用；线下私下交接不构成系统认可的合法流转 | 未来库存不得以业务员间自由转移替代正式责任关系 |
| K-10 | 入库、转用、还回、异常和植入均分别改变或解除来源订单责任；O01展示结果，O04保存正式历史 | 库存若提供结果，必须保留可追溯来源与结果关系，不能覆盖原订单事实 |
| K-11 | 已接收实物的数量守恒包含：实际植入、公司确认还回、批准转个人仓、批准转入本人其他订单、批准异常处置和在手待结余 | 这是相邻模块不可违反的责任守恒式；未来库存的数量模型不能悄然吞掉其中任何一项 |

### 3.3 还回、异常和器械包放行边界

| 编号 | 已确认外部约束 | 对未来库存的含义 |
|---|---|---|
| K-12 | 还回是待结余下的一条去向；公司确认还回并完成必要清点后才解除相应业务员责任 | 不得把发起还回、运输或公司受理直接当作库存可用／责任解除 |
| K-13 | 接收前异常由T03处理；接收后的在手异常由O01组件处理；还回后清点差异留在S01 | 异常可共享表单能力，但三种责任发生点不同，不能在库存中合并为一个无来源的异常状态 |
| K-14 | 器械包公司确认还回后，本订单中的业务员保管责任可以解除；订单完成不等待后续器械处理 | 器械后续处理不反向阻塞订单闭环；未来库存／器械能力需分清“责任解除”与“再次可用” |
| K-15 | 器械包进入业务员下一张订单前，必须有公司确认的可用／放行结果 | “可用／放行”是外部依赖结果，尚未定义其生成流程、页面、模块或权限；不得将其命名或推导为独立消毒模块 |

### 3.4 手术植入的来源与回写边界

| 编号 | 已确认外部约束 | 对未来库存的含义 |
|---|---|---|
| K-16 | 实物销售明细按“产品＋批号／可追溯身份（如有）＋数量”记录来源分配，可混合来源 | 未来库存与植入交界至少要能保留实物来源粒度；不代表已确定库存表结构或扣减动作 |
| K-17 | 当前确认的植入来源类别为“业务员自有库”与“本次手术需求组已接收且仍绑定的通知候选实物” | 两类来源可混合；仅通知来源部分回写手术通知责任与结余 |
| K-18 | 正式植入取消／失效只反向调整原通知来源；销错冲正先反向原来源，再正向正确结果 | 这定义通知责任回写顺序，不定义库存恢复、拆损、质检、扣减或补偿 |
| K-19 | 未正式形成、自动校验异常、补齐重提、放弃或超期退出不回写手术通知 | 不能将未形成销售正式结果误作库存或订单责任的自动变动依据 |

## 4. 已登记但未闭合的库存相关桩子

| 编号 | 桩子 | 当前已知边界 | 未来归属／恢复条件 |
|---|---|---|---|
| P-K01 | “业务员自有库”与“个人仓等其他合法来源”术语关系 | 当前资料未确认二者是否同义、包含关系或不同来源类别 | 库存管理启动时，与手术植入／手术通知共同确认；当前不得合并术语 |
| P-K02 | 个人仓审批、最低库存和库存计算 | 仅确认转入个人仓须批准后生效 | 库存管理规则与相应Web接口；当前无审批、阈值或计算规则 |
| P-K03 | 库存可用量、扣减、入库、调拨和恢复 | 多处资料明确不由通知或植入模块定义 | 库存管理模块；不得由销售、植入、接收或冲正自动推导 |
| P-K04 | 实物来源自动匹配与细分分摊 | 拆盒后单件不可追溯、同一实物多来源时的识别与分摊未确认 | 库存与通知／植入接口；不改变当前来源原则 |
| P-K05 | 器械包可用／放行结果形成 | 仅确认其是转入下一订单前的外部结果 | 后续器械或库存相关能力；当前不建立流程、页面或独立模块 |
| P-K06 | 接收后在手异常的库存影响 | 当前只确认责任冻结与由公司形成正式处置结果 | 库存管理与异常处理边界；不得直接核销、回补或变为可用库存 |
| P-K07 | 还回、清点和跨订单交寄的库存／后台呈现 | 当前只确认来源订单、实物身份和责任必须分别保留回写 | 未来库存／Web模块；APP不定义后台呈现或清点流程 |
| P-K08 | 技术接口与控制字段 | 幂等、重试、字段、权限、时限、审批角色均未确认 | 对应APP／Web／库存接口阶段 |

## 5. 当前资料中的边界性否定结论

这些是否定已有越界推断，不等于未来永远不存在该能力：

- 手术通知不是库存查看、采购、调拨、入库或仓库操作页；
- 手术植入不是库存扣减、回补、拆损、质检、退货或个人仓审批页；
- 正式销售结果、取消、失效和冲正不能被静默翻译为库存处理；
- 库存与各Web后台尚未启动，不能从常见ERP做法补出仓库、库位、批次、盘点、审批或报表；
- G01虽然保留“库存管理”入口位置，但该入口不是库存模块规则、页面或任务已经存在的证明。

## 7. 未来库存模块的承接清单

库存管理正式启动时，先对下列问题做业务规则讨论与逐项确认，而不是直接画页面：

1. 库存模块的业务目标、对象边界、角色和正式结果；
2. 自有库、个人仓、公司仓及其他合法来源的术语和关系；
3. 实物身份、批号／序列号、器械包与拆分粒度；
4. 哪些正式结果形成可用量、锁定、转入、转出、扣减、恢复或异常责任；
5. 个人仓申请与批准的责任、触发、结果回写和失败恢复；
6. 与手术通知的已接收实物、待结余、转用、还回、异常和器械放行结果的接口；
7. 与手术植入来源分配、取消／失效、销错冲正的接口边界；
8. 与未来Web后台的职责分工、审批与技术契约。

以上是**启动问题清单**，不是已确认答案。库存模块建池后，任何一项结论均须单独写入其规则池／接口池，并在影响手术通知或手术植入时回写双方接口资料。

## 8. 维护规则

- 其他模块形成库存相关的当前有效结论时，先更新其原始规则或接口，再在同一轮把“可继承约束／桩子／来源”补入本归档；
- 本归档不汇总聊天、猜测、行业惯例或历史已替代方案；
- 资料冲突时记录来源与影响，暂停受影响条目，不由本归档自行裁决；
- 库存模块一旦建立正式总池，本文件继续作为跨模块候选索引，不自动升级为库存事实源。
