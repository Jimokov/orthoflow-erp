# 跨模块候选资料说明

> 状态：当前有效的候选沉淀机制说明；不保存业务事实，不替代模块总池、规则池、接口池、页面资料或跨模块遗产索引。

## 1. 三层资料的分工

| 资料 | 唯一职责 | 可写内容 | 不可写内容 |
|---|---|---|---|
| 跨模块遗产索引 | 定位已确认的交叉事实与稳定桩子 | 已确认输入、输出、责任、回写、术语边界、来源 | 探索想法、未确认方案、模块内部设计 |
| 库存管理候选资料归档 | 保存未来库存必须继承的外部约束与启动问题 | 已确认外部约束、稳定共同桩子、来源 | 库存内部规则、原始讨论、候选方案 |
| 库存相关探索候选簿 | 保存可复用、待库存模块论证的探索候选 | 已约束的候选、触发场景、未知点、潜在影响和未来归属 | 已确认库存事实、页面、审批、扣减或技术协议 |

## 2. 候选的登记门槛

只有同时满足下列条件才登记候选：

1. 它来自一个已记录的当前业务场景，而不是聊天片段或行业惯例；
2. 它可能影响未启动模块或两个以上模块；
3. 当前拥有事实的模块尚不能裁决，或裁决需要未来模块参与；
4. 能够写明已知边界、未知内容与未来论证归属。

不满足时，继续留在当前模块的探索记录或桩子中，不制造跨模块资料。

## 3. 候选的固定字段与生命周期

每条候选必须写明：候选编号、触发场景、候选描述、直接依据、尚未确认内容、可能影响、未来归属、状态与退出条件。

状态只可为：`候选收集`、`等待所属模块论证`、`已确认并已转入`、`不采用`。前两种不构成事实；后两种必须链接目标模块的正式去向或拒绝理由。

候选被确认后，先更新拥有事实的模块规则／接口／页面资料，再更新遗产索引；候选簿只保留去向，不复制事实正文。

## 4. 相邻模块发现待论证清单

当一个模块发现另一个已启动模块可能需要补充论证时，不直接修改对方当前事实。发现方在目标模块的“跨模块发现待论证清单”登记：发现来源、已知事实、待论证问题、可能影响和建议审查位置。

目标模块后续对话只把该条目当作论证入口：可以确认、拒绝或保留为桩子；确认结果必须回到目标模块的正式事实资料，再回填清单和遗产索引。
