# 跨模块遗产索引 v0.1

> 身份：项目级跨模块继承索引。它定位已经在一个正式模块中论证、并会约束相邻模块的交叉事实、桩子与来源；不替代任一模块的总池、规则池、接口池或页面资料。
>
> 建立日期：2026-08-27  
> 当前覆盖：APP－手术通知、APP－手术植入，以及面向手机 APP 下库存管理功能模块的已知外部约束。

## 1. 使用目的与边界

一个模块完成阶段性讨论后，除本模块内部结论外，其中已经确认的跨模块对象、输入、输出、责任、结果回写和未闭合点，也应成为后续模块的可继承遗产。本索引负责让后续任务先知道这些交叉信息已经在哪里被讨论和沉淀，避免重新依赖旧聊天解释。

本索引采用“原模块保留主线＋项目级索引定位交叉遗产”的两层方式：

- 原模块的完整继承基线、规则池和接口池仍是事实正文与裁决来源；
- 本索引只汇总已确认的交叉结论、继承方向、尚未闭合桩子和正式来源；
- 索引摘要与来源正文冲突时，以来源正文为准，并暂停受影响的继承；
- 未启动模块只能读取与记录候选约束，不能据此生成内部状态、页面、审批、后台能力或技术协议。

## 2. 新模块的最小继承顺序

1. 读取项目范围登记、目标模块总池及根 `CONTEXT.md`；
2. 在本索引中定位与目标模块直接相关的遗产条目；
3. 读取条目列出的来源模块完整继承基线与直接规则／接口正文；
4. 将“已确认事实”作为不得违反的边界；将“桩子”作为启动后待讨论清单，不当作答案；
5. 若需要新增输入、输出、责任、正式结果或回写，先由双方确认接口并回写各自资料，再更新本索引。

不读取旧聊天来补充任何条目。

## 5. 明确不继承的内容

- 手术通知的 C／O／T／S 页面内部结构、八种订单主状态及公司履约流程，不自动成为植入或库存的页面和状态；
- 手术植入的患者、销售形态、凭证、校验与销售结算内部规则，不自动成为手术通知或库存规则；
- 库存管理功能模块已启动资料审校，但库存内部操作、审批、仓库模型、页面和技术接口仍未确认；各 Web 后台尚未启动，任何此类能力均不因本索引而成立；
- 探索记录中的候选界面、操作方式与未确认细节，不作为继承事实。

## 6. 维护与版本规则

1. 先修改拥有该事实的模块规则／接口正文，再同步本索引的条目、来源或桩子；
2. 条目被替代、拆分或合并时，保留原编号、替代关系及影响模块，不静默覆盖；
3. 一个新模块启动时，仅将直接相关条目带入其启动盘点；其内部规则须再次确认并写入自身资料池；
4. 本索引当前版本为 `v0.1`；新增可继承模块或交叉领域时按项目版本规则迭代。
