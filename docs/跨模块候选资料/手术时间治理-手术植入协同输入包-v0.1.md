# 手术时间治理—手术植入协同输入包 v0.1

> 身份：跨模块候选协同输入包。
>
> 用途：供 T1 手术植入在不重开手术通知规则的前提下，论证实际手术时间与植入记录时限；本文件不新增手术通知或手术植入事实、字段、任务、时限、处罚、页面、权限或技术接口。
>
> 接收方：APP－手术植入当前任务。完成后由手术植入先写入其拥有的正式资料，再携带正式去向返回本专案完成共同契约。

## 1. 本次协同要验证的样本链

```text
手术通知的当前有效计划手术时间
→ 时间已过但无有效结果时的手术情况确认
→ 进入同一台手术的植入记录
→ 植入侧形成正式结果
→ 回写通知，关闭原确认任务并重算订单责任
```

目标不是先确定“三天原则”，而是验证这条已存在的跨模块链如何承载“实际手术时间—正式植入记录—可能的时限责任”，且不产生重复催办。

## 2. 手术通知已确认、必须继承的边界

| 编号 | 已确认事实 | 手术植入不得改写的边界 |
|---|---|---|
| N-01 | 计划手术日期与准确时间必填；延期正式生效后原计划时间失效，已知新时间经正式变更生效。 | 植入引用当前有效计划时间与订单上下文，不拥有或改写计划时间。 |
| N-02 | 当前有效计划时间已过且无有效植入、有效延期或有效取消时，形成“手术情况确认”任务；O01 与 G03引用同一任务。 | 从该任务进入植入，只是完成路径，不等于已经形成结果或可以关闭原任务。 |
| N-03 | 只有正式植入结果及可追溯更正会改变通知责任；取消、失效或冲正后，通知撤销原回写并按当前有效事实重算，必要时重新生成手术情况确认。 | 草稿、自动校验异常、补齐重提、放弃或超期退出不回写通知。 |
| N-04 | 手术通知内部已承载计划时间、无结果确认与订单内借单还回；当前不定义具体提醒阈值、推送或时间计算口径。 | 不将植入侧时限候选倒灌为通知既成规则，也不新建通知页面或任务。 |

直接来源：[手术通知核心业务规则 v1.6](../../modules/APP-手术通知/01-规则池/01-手术通知APP核心业务规则-v1.6.md) §11、§13—§14；[手术通知—手术植入双向结果接口 v0.3](../../modules/APP-手术植入/02-接口池/01-手术通知双向结果接口-v0.3.md)。

## 3. 需要由手术植入论证的事项

手术植入应只在自己的当前任务与规则边界内，逐项确认或保留桩子：

1. **实际手术时间事实**：是否采集、与一次实际手术事件的关系、来源凭证、形成与正式更正的边界；
2. **记录完成事实**：何时视为“正式植入记录已形成”，与未完成、自动校验异常、补齐重提、放弃或超期退出的关系；
3. **三天原则候选**：它想治理的究竟是哪项独立责任、依附哪项可靠事实、何时开始／暂停／失效，以及逾期后的管理结果类别；
4. **任务去重**：它与既有“手术情况确认”是同一责任的进入步骤，还是形成新的“按时完成正式记录”责任；若为后者，二者如何分别关闭；
5. **更正与回写**：实际时间、正式记录取消／失效／冲正后，哪些植入侧结果需要重新判断，哪些通知侧重算继续由既有接口承担。

以上问题未确认前，不应预设 OCR、具体字段、三天起算点、处罚方式、推送、G01／G03页面表现或 Web 后台能力。

## 4. 共同去重原则

本次协同暂按下列已确认的专案共同框架审查：

- 时间事实拥有者、当前责任拥有者、任务拥有者与呈现消费者必须可区分；
- 同一对象上的同一未完成责任只能有一个任务来源，多页面只引用，不复制催办；
- 植入正式结果回写后，通知侧原“手术情况确认”任务关闭或重算；
- 未来若三天原则形成独立责任，必须证明其动作、完成条件、事实来源和退出链均不同于“确认手术情况”。

这些是跨模块候选框架，不替代手术植入的正式规则。

## 5. 手术植入完成后的回传标准

返回手术时间治理专案前，请携带：

1. 已确认的实际手术时间／正式记录关系及其正式资料链接；
2. 三天原则是否形成正式规则、保留桩子或不采用，以及理由；
3. 与既有手术情况确认任务的去重判断；
4. 对通知的最小输入、输出与重算影响；
5. 本轮修改文件、提交编号与未进入范围。

手术时间治理专案收到这些正式去向后，才讨论共同契约是否成立、需要向手术通知回写什么，以及是否进入全局任务与提醒承载。

## 6. 明确不进入

- 不重开手术通知的计划时间、订单状态、O01／T／S页面或借单还回规则；
- 不提前规定库存相关入库、还回运输、公司后台、权限、处罚或技术实现；
- 不将本输入包或未确认的三天原则当作手术植入当前事实。
