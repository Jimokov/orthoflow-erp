# 项目驾驶舱与进度记录规范

> 状态：当前有效  
> 生效日期：2026-08-23

## 1. 三类资料的身份

| 资料 | 唯一职责 | 是否为当前业务事实源 |
|---|---|---|
| 根目录 `README.md` | 项目驾驶舱：说明现在在哪里、当前唯一任务、下一步、阻塞和恢复点 | 否；其中摘要必须能追溯到正式资料 |
| 模块总池、规则池、接口池、设计池、代码池、验收池 | 保存当前确认的业务、设计和实现事实 | 是 |
| `docs/progress/DAILY` 与 `WEEKLY` | 保存当日、当周发生过什么 | 否；是带日期的历史快照 |

驾驶舱和日／周记录不得独立发明业务结论。摘要与正式资料冲突时，以正式资料为准，并立即修正驾驶舱；日／周历史保留当时表述，必要时增加后续更正说明，不静默改写历史。

## 2. 驾驶舱必须回答的问题

根 `README.md` 必须让用户在一屏到数屏内获得：

1. 当前主模块、端和阶段；
2. 当前唯一任务与正在生效的硬闸门；
3. 已完成的重要里程碑；
4. 接下来三步；
5. 阻塞项和非阻塞桩子；
6. 本周与今日摘要；
7. 文档健康状态；
8. 明日或下次恢复点；
9. 可点击的正式资料入口；
10. 快照的更新时间与事实截止时间。

进度使用阶段状态，不使用没有客观口径的完成百分比。推荐状态包括：未启动、宏观审查中、逻辑讨论中、阶段性收束、已确认、已通过闸门、待全流程验收、待低保真、阻塞。

## 3. 日记录

工作日形成有效结论、更新正式资料或执行收工整理时，建立或更新 `DAILY/YYYY-MM-DD.md`。只记录：

- 今日目标；
- 实际完成；
- 确认或改变的关键结论；
- 新增、关闭或改变阻塞性的桩子；
- 修改的正式资料；
- 当前唯一任务是否变化；
- 下次恢复点；
- Git提交与远程同步结果。

同一天持续更新同一文件，不按聊天轮次制造多份日报。没有形成业务结论时明确写“未改变业务基线”。

## 4. 周记录

有工作发生的自然周维护 `WEEKLY/YYYY-Www.md`。周记录汇总：

- 本周目标；
- 通过的阶段与硬闸门；
- 正式页面、模块或规则集合的变化；
- 仍未闭合的阻塞和桩子；
- 下周主线；
- 本周日报与关键提交索引。

周记录不复制全部日报，不按提交数量评价进度。

## 5. 开工与收工协议

### 开工

1. 读取根 `README.md` 的当前唯一任务和恢复点；
2. 按项目 Skill 读取范围登记和目标模块资料；
3. 若驾驶舱与正式资料冲突，先报告并修复当前快照，再推进新业务。

### 收工

1. 把有效结论写入所属正式资料；
2. 更新模块首页、当前进度和当前唯一任务；
3. 更新根 `README.md` 的当前状态、里程碑、桩子和恢复点；
4. 更新当日日报；周目标或周状态变化时同步周报；
5. 检查驾驶舱中的每项完成、阻塞与下一步都有正式资料依据；
6. 限定本次范围提交并推送，记录远程验证结果；
7. 驾驶舱未对齐或远程状态无法验证时，明确报告收工未闭合。

## 6. 更新触发器

出现以下任一变化必须更新驾驶舱：

- 当前唯一任务变化；
- 模块、阶段或页面组开始、收口、删除、融合或通过闸门；
- 正式页面总数变化；
- 阻塞项或桩子的阻塞性变化；
- 进入或退出全流程验收、低保真、视觉、代码或验收阶段；
- 项目明确暂停、转向或恢复；
- 现有首页摘要被发现滞后或失实。

仅修正文案、格式、链接或Skill而不改变业务进度时，可以只更新今日记录和驾驶舱的维护日期，不得伪造业务里程碑变化。
