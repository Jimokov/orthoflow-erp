# 项目驾驶舱与进度记录规范

> 状态：当前有效
>
> 生效日期：2026-08-23

## 1. 三类资料的身份

| 资料 | 唯一职责 | 是否为当前业务事实源 |
|---|---|---|
| 根目录 `README.md` | 项目驾驶舱：说明现在在哪里、当前唯一任务、下一步、阻塞和恢复点 | 否；其中摘要必须能追溯到正式资料 |
| 模块总池、规则池、接口池、设计池、代码池、验收池 | 保存当前确认的业务、设计和实现事实 | 是 |
| `docs/progress/DAILY` 与 `WEEKLY` | 保存当日、当周发生过什么 | 否；是带日期的历史快照 |
| `docs/progress/任务与对话承接矩阵.md` | 保存全部活动任务的类型、来源、正式资料入口、状态、阶段、恢复点、下一入口和承接条件 | 否；不保存业务事实 |

驾驶舱和日／周记录不得独立发明业务结论。摘要与正式资料冲突时，以正式资料为准，并立即修正驾驶舱；日／周历史保留当时表述，必要时增加后续更正说明，不静默改写历史。

## 2. 驾驶舱必须回答的问题

根 `README.md` 必须让用户在一屏到数屏内获得：

1. 当前主模块、端和阶段；
2. 当前唯一任务与正在生效的硬闸门；
3. 已完成的重要里程碑；
4. 接下来三步；
5. 阻塞项和非阻塞桩子；
6. 当前周目标和日／周进展入口；
7. 文档健康状态；
8. 明日或下次恢复点；
9. 可点击的正式资料入口；
10. 快照的更新时间与事实截止时间。

进度使用阶段状态，不使用没有客观口径的完成百分比。推荐状态包括：未启动、宏观审查中、逻辑讨论中、阶段性收束、已确认、已通过闸门、待全流程验收、待低保真、阻塞。

## 3. 日记录

当天实际推进项目并形成有效结论、修改项目资料或由用户要求收工整理时，建立或更新 `DAILY/YYYY-MM-DD.md`。只记录：

- 今日目标；
- 实际完成；
- 确认或改变的关键结论；
- 新增、关闭或改变阻塞性的桩子；
- 修改的正式资料；
- 当前唯一任务是否变化；
- 下次恢复点；
- Git提交与远程同步结果。

同一天持续更新同一文件，不按聊天轮次制造多份日报。只有探讨、没有形成业务结论时，可以只记录“未改变业务基线”和下次恢复点；当天没有实际项目工作时不创建空日报。

### 当日恢复信息

每份当日日报记录当天发生的实质变化、当前恢复点和必要来源。每个 Codex 对话线程从 `01` 起编号，跨自然日继续沿用该线程序号；日期和线程 ID共同用于定位，以 [对话编号登记](对话编号登记.md) 为准。日报不是业务事实，也不要求逐条复制聊天内容。

## 4. 周记录

建立周目标、周目标变化、通过重要里程碑或周末收口时维护 `WEEKLY/YYYY-Www.md`。普通日报不触发周报改写。周记录汇总：

- 本周目标；
- 通过的阶段与硬闸门；
- 正式页面、模块或规则集合的变化；
- 仍未闭合的阻塞和桩子；
- 下周主线；
- 本周日报与关键提交索引。

周记录不复制全部日报，不按提交数量评价进度。

## 5. 开工与收工协议

### 开工

1. 新对话先读取根 `README.md`、[任务与对话承接矩阵](任务与对话承接矩阵.md)和最近有效日报，完成轻量项目任务脉冲：确认全部活动任务、各自阶段、恢复点、下一入口和直接依赖；不全量读取其他模块正文；
2. 读取当日日报的当前恢复信息；
3. 读取[对话编号登记](对话编号登记.md)，为当前对话线程分配下一个序号；同一线程跨日续接时继续递增，日期字段随当前日期变化；
4. 读取范围登记、目标模块资料，以及本轮直接相关的当前有效资料和跨模块接口；
5. 新建或迁移完成的模块，先核对模块总池、启动路线图、当前规则基线、接口登记及适用的历史索引是否齐备；缺失时先补资料包，不推进业务候选；
6. 核对当前唯一任务、恢复点、继承事实和接口是否一致；若发现冲突、缺口或需要聊天记忆，先报告并停止业务提问；
7. 当日首次业务推进说明当日唯一目标、当前审查或推进位置和不进入范围；只有存在真实业务取舍时说明待用户决定的事项。不把启动盘点扩张为全量重读。

新对话的项目任务脉冲与每日首次业务启动是两个触发条件：前者用于发现并行任务，后者用于当天资料和编号盘点；二者都只读取最小必要集合。

### 收工

收工采用增量更新，不等于读取或改写全部页面：

| 当天变化 | 必须更新 | 不因此自动更新 |
|---|---|---|
| 只有讨论，未形成确认结论 | 当日日报中的“未改变业务基线”和恢复点 | 正式资料、模块首页、驾驶舱、周报 |
| 同一任务内形成局部结论 | 直接承载结论的正式文件、当日日报 | 无关规则、接口、页面清单、流程、设计总控、驾驶舱 |
| 当前唯一任务、阶段、页面组或恢复主线变化 | 直接资料、模块首页、当前进度、驾驶舱、当日日报 | 无关页面正文 |
| 页面增删融合、状态、入口、流程、权限或结果回写变化 | 所属正式文件及受影响的清单、流程、总控、规则或接口 | 未受影响文件 |
| 页面总数、硬闸门、项目边界或桩子阻塞性变化 | 受影响正式资料、模块首页、驾驶舱、当日日报；适用时更新周报 | 无关模块资料 |
| 组间切换或全流程验收 | 按对应硬闸门执行全量筛查和对齐 | 无关工作区改动 |
| 只修改工作方法、Skill、格式或链接 | 直接文件和当日日报；驾驶舱仅在其显示信息变化时更新 | 业务规则、页面资料和模块进度 |

随后限定本次范围提交并推送，记录远程验证结果。只有表中适用的资料和Git远程状态完成对齐后，才能报告收工闭合；不以“所有文件都被重新读取或改写”作为完成条件。

收工分为两层：先整理当前任务实际变化，再增量检查项目任务索引是否新增、暂停、恢复或完成任务，或主任务、阶段、依赖和驾驶舱摘要是否变化。没有项目级变化时，只记录“项目活动任务无变化”，不重读无关模块。发生需要跨对话或跨端继承的资料变化时才必须提交并推送；只有讨论、无资料变化时不制造提交。

## 6. 更新触发器

出现以下任一变化必须更新驾驶舱：

- 当前唯一任务变化；
- 模块、阶段或页面组开始、收口、删除、融合或通过闸门；
- 正式页面总数变化；
- 阻塞项或桩子的阻塞性变化；
- 进入或退出全流程验收、低保真、视觉、代码或验收阶段；
- 项目明确暂停、转向或恢复；
- 现有首页摘要被发现滞后或失实。

未命中上述触发器时不修改驾驶舱。仅修正文案、格式、链接或Skill而不改变业务进度时，只更新直接文件和适用日报；只有驾驶舱展示的版本、健康状态或入口发生变化才更新本页摘要，不得伪造业务里程碑变化。
