# 任务与对话承接矩阵

> 状态：当前有效的任务关系索引
> 建立日期：2026-08-24
> 作用：管理全部活动任务如何承接、旧对话如何一次性迁移及下一任务的进入条件；不保存业务事实。

## 使用规则

- 每个任务只标注一种类型：全新承接、历史迁移或正常续接。
- 本矩阵登记项目当前仍需承接、推进、等待确认或保留恢复点的活动任务；项目主线只是驾驶舱排序，不代表唯一活动任务，也不得替代对话绑定。历史任务和已退出职责的旧对话不计入当前活动任务。
- 业务事实只存在于模块总池、规则池、接口池、设计池、代码池或验收池；本矩阵只链接这些正式资料。
- 历史迁移中的候选不是事实，必须经用户确认并写入正式资料后，才可被后续任务继承。
- 旧对话完成迁移后退出业务推进职责；新任务不得再将其历史当作背景补充。
- 当前表格尚未拆列的阶段、恢复点或下一入口，可以继续由“状态”“下一承接任务”“转换条件”和正式入口共同承载；只有任务发生变化时才增补或拆分字段，不为治理发布重写历史行。
- 每个活动任务必须有唯一 `Tn` 标识和对话绑定状态。一个活动对话同一时刻只绑定一个 `Tn`；切换须由用户明确指定，并先更新本矩阵后读取新模块正文。共享机制可以被多个任务使用，但不得登记为可自动承接的独立对话任务。
- 来源／承接对话可同时登记本日对话回复编号和 Codex 系统线程 ID；本日编号用于当天回复定位，系统线程 ID用于跨对话、跨端唯一追溯。线程标题只用于协助定位，不替代系统线程 ID。
- 当前活动任务按集合 `T1…Tn` 管理；每个任务可独立收尾和更新自身状态，全部项目是否收口由集合中所有任务的状态汇总判断，不因某一任务收尾而覆盖其他任务。
