> 建立日期：2026-08-24
> 范围：只论证旧对话 `019fb68d-d9a1-7192-b15a-90330c470771` 是否可被安全迁移；不读取旧对话正文，不形成任何手术植入业务结论。

## 1. 当前事实与风险

- 当前范围登记将手术植入列为“已有完整构想”，但明确要求先盘点、辨别当前版本与历史版本，再单独建池；当前不存在手术植入正式总池。
- 旧对话未按现行项目 Skill 与资料池机制推进。若直接续聊，历史结论、未确认猜测和已被替代内容会混入新任务，无法追溯或验证。
- 因此，旧对话只能作为一次性候选来源，不能成为后续业务事实来源或持续工作场所。

## 2. 拟议迁移边界

| 项目 | 迁移时允许做什么 | 不允许做什么 |
|---|---|---|
| 来源 | 仅盘点指定旧对话与其中明确指向的既有项目文件 | 搜索其他旧聊天；把聊天记忆当作事实 |
| 条目 | 摘取候选规则、对象、页面／流程、跨模块衔接、冲突与缺失 | 补写规则、创建页面、推演后台、设计代码 |
| 结果 | 输出逐条候选清单及来源定位 | 直接建立正式规则、接口、页面清单或模块总池 |
| 确认 | 等用户逐项或按组确认后，才写入正式资料 | 以“旧对话已有共识”替代用户确认 |

## 3. 候选清单的最小格式

每条候选必须包含：

1. 唯一候选编号；
2. 来源线程及可定位的原始位置；
3. 原始表述的简要释义；
4. 对象与可能影响范围；
5. 与当前手术通知正式资料的关系：可继承、冲突、重复、缺失或无关；
6. 推荐去向：规则、接口、设计候选或不迁移；
7. 状态：`未确认`。

候选清单不使用“当前有效”“已确认”或“正式页面”等状态词。

## 4. 成功、停止与退出条件

### 成功条件

- 已完整列出可识别候选和无法确认项；
- 每项可回到具体来源，不以概括性聊天记忆充数；
- 与当前手术通知接口的冲突、重复和缺失已经单列；
- 用户确认哪些候选可以进入正式资料，以及手术植入是否达到建池条件。

### 停止条件

出现以下任一项立即停止盘点并请求用户决定：来源无法定位；候选彼此矛盾且当前资料无法裁决；候选需要依赖未讨论的 Web／库存／其他模块；旧对话开始试图继续业务讨论而非盘点。

### 退出条件

用户确认迁移清单处理完成后，更新范围登记与任务矩阵，建立手术植入正式总池或明确暂不建池；旧对话退出业务推进职责，后续任务只从已写入的资料池继续。
