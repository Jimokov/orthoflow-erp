- 手术通知、手术植入仅按其已确认的跨模块结果契约参与；本业务域不补写其内部规则、页面或状态机。

## 3. 当前唯一任务

在已确认的概念关系基础上，厘清公司库存、常备物资、临时物资、保管形态与责任之间的边界；判断最低库存应附着的关系及其设定责任。

本阶段不进入 APP／Web 功能、页面、岗位、审批、自动化、技术接口、库存计算或操作规则。

### 阶段性探索基线（2026-09-01）

- 同一实物跨业务时，暂以稳定实物身份和连续业务服务关系保持责任与追溯连续。
- 归还、异常等事件是否形成正式结果，按其稳定业务后果、承接、责任变化或追溯需要判断。
- 责任变化按发起者、成立依据、生效时点和承担者四个维度继续验证。

以上是用户确认的阶段性探索基线，不是正式对象、规则、状态或端能力。

### 库存层级与机制作用域基线（2026-09-02）

- 公司库存按两级结构理解：一级是公司管理并实际持有、管理进出的公司库存；二级是以医院为绑定边界的统一二级库存。
- 一家医院原则上只设一个二级库存；同一家医院可以由一个或多个业务员服务，业务员与二级库存的绑定由公司后台管理，不预设一对一关系。
- 业务员日常面向自己关联的二级库存，但手术通知是面向公司全域库存的要货需求；具体供给、绑定和履约关系由公司后台决定。
- 最低库存机制的作用域是二级库存；一级还需要一个覆盖公司库存进出业务的动态联动机制，当前不强行命名或确认其具体规则。
- 公司库存是向外开放的二层供给体系：一级公司总库存承接公司实物与外部资源关系；医院二级库存同时是公司库存第二层和面向医院的供给、交付关系层，不能把两者拆成内外二选一。
- 无论实物后续服务哪个医院二级库存，对外来源、归还或结算责任始终保留在公司一级；医院二级和业务员不替代该责任。
- 当前实际保管形态包括医院代管与业务员自持；两者均统一纳入对应医院二级库存管理，所有库存管理均隶属公司并由业务员执行，保管形态不自动改变二层结构或公司一级的对外责任。未来寄售模式仅为阶段二桩子。
- 医院二级库存区分供给配置、实物供给／交付和具体手术用途三层关系；三层相互关联但不互相替代。
- 一级公司配置服务公司整体供给，医院二级配置服务单家医院供给准备；二者联动但不互相替代，一级不等同于二级配置的机械相加。
- 医院二级库存的常备／常规物资由最低库存机制管理；临时物资面向具体业务需要临时进入供给关系，实际到达并进入医院供给管理范围后也纳入该医院二级库存，但不纳入该机制。
- 临时物资可来自多个尚未穷尽的业务来源；来源目录与履约分流留待后续阶段确认。
- 可用性分为医院二级当前可用和公司整体按时可履约；两者不互相替代，当前不定义来源选择、时间算法或履约动作。
- 公司供货承诺不等于具体实物绑定；未选定具体实物时不自动产生绑定或占用。
- 公司库存形成供货承诺，手术通知形成需求并承接该正式供给结果；具体实物绑定仍由后续有效业务流建立。
- 实际业务结果由实际发生业务形成，公司库存读取正式结果并改变自身实物关系；总库自身直接改变实物关系的管理行为可形成库存结果。
- 每次实物关系变化保留前一关系、新关系与触发变化的有效业务流；稳定实物身份及公司一级对外来源责任始终不断链。
- 稳定实物身份在任意有效业务流锁定具体实物时，与相应业务建立绑定关系；预留、占用、登记是其可能作用，不是固定三状态。
- 有效业务绑定建立用途责任，但不自动改变持有责任、可用性或结果责任。
- 手术通知不直接占用具体实物；只有有效业务流明确锁定具体实物给具体手术时，绑定才产生占用作用。
- 占用关系的变化必须由可追溯的有效业务流完成；总库自动或人工管理行为可发起变化，但不是变化结果本身。

以上为用户确认的宏观结构基线；“动态联动机制”只是当前描述性称呼，不是正式术语或系统能力。

## 4. 当前桩子

业务对象的定义、盘点、可用性、最低库存的附着关系与业务后果、履约方式、库存变化与跨模块回写均未确认；用户新增的“销售统计—配置建议—申请调整—调拨／采购／外借”闭环暂作为 T4 待论证输入，须在本业务域的后续阶段逐项澄清，不得由 T2 的候选输入或既有称呼自动继承。

二级库存的医院边界、单医院一个统一二级库存、业务员多对一服务关系、后台配置绑定、业务员要货面向公司全域库存，以及一级实际持有和管理公司实物，已按 2026-09-02 用户确认形成结构基线；具体对象粒度、责任结果和动态联动规则仍待论证。

医院二级库存面向具体计划手术的预留、占用与登记关系已纳入当前待论证对象；其关系区分、建立与解除时点、可用性影响和跨模块边界仍待确认，不形成操作规则。

绑定关系的集中管理形态及其对可用性、持有责任、用途责任和结果责任的具体影响仍待论证。
