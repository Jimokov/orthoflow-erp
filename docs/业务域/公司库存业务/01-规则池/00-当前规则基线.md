## 2. 可核验的外部约束（非公司库存内部规则）

- 项目范围当前已将 APP－库存管理 T2 和库存 Web 后台明确分开；后者尚未启动。
- 已接收的手术通知实物先形成来源订单的在手待结余责任，不自动成为业务员侧常备物资。
- 手术植入的实物销售来源追溯至少涉及产品、批号／可追溯身份（如有）与数量；植入结果、取消／失效和冲正当前只确认通知责任回写边界。

直接来源：项目范围登记、T2 当前规则基线与接口登记所列直接来源。以上为 T4 的审查起点，不等于公司库存业务规则。

## 3. 未继承范围

- 不继承“自有库／个人仓”、最低库存、自动补货、基础盘点、常备转入等候选输入为公司库存事实。
- 不继承任何 APP 或 Web 页面、角色、审批、技术接口、库存计算或操作方式。

## 3.1 已登记的后续论证议题（不是规则）

现有 APP－库存管理资料中的 I-K04 与 P-K02 已提到“最低库存”，但只作为待确认输入／桩子进入 T4 的后续论证：先在库存域边界与责任阶段确定它附着的关系和责任，再在数量与事件阶段验证比较口径，最后在需求缺口与履约分流阶段判断其业务后果。当前不确认最低值、触发条件、自动补货或任何端能力。

## 4. 当前桩子

公司库存的对象层级、实物归属、可用性、责任、事件、正式结果、追溯及其与相邻模块的关系，均待 T4 阶段性澄清。
