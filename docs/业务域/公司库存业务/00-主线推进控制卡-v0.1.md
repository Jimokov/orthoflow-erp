# 公司库存业务：主线推进控制卡 v0.1

> 状态：当前有效的 T4 推进控制载体。  
> 身份：只控制讨论归位与推进节奏；不承载任何公司库存业务事实、规则、接口或端能力。  
> 建立日期：2026-09-02。

## 绑定范围

本控制卡只绑定 T4“公司库存业务宏观逻辑规划”。当前执行 [启动路线图](./00-启动路线图-v0.1.md) 的阶段一“概念与核心关系”。

当前阶段目标是确认公司库存宏观逻辑中的概念、关系与待确认对象；不是讨论某一项机制、某一个端模块或某一个场景。

## 主线与材料的区分

- **主线**：按启动路线图依序完成公司库存宏观逻辑规划。
- **当前阶段工作**：在不进入后续机制和履约细节的前提下，确认概念与核心关系。
- **结构前提**：已确认的一二级库存、医院边界、后台绑定和公司全域要货关系，必须持续约束后续讨论，但不因此成为新的推进主线。
- **后续机制输入**：最低库存、公司级动态联动、采购、借物、调拨等，按路线图所属后续阶段停放；除非用户明确切换，不占用当前讨论。
- **相邻业务边界**：手术通知与手术植入只提供已确认的需求、实际结果与追溯边界；不把其内部流程带入 T4。
- **验证载体**：关系图、表格和场景只用于说明或检验当前判断，不能取代当前阶段目标，也不能自行产生新议题。

## 新输入的处理

每条新输入只先做一次归位：

| 输入性质 | 处理 |
|---|---|
| 直接改变当前阶段概念或关系的事实／确认 | 纳入当前推导，并说明它改变的是哪一项当前判断。 |
| 已确认结构前提的补充 | 作为后续推导的固定约束使用，不另起讨论链。 |
| 后续机制、履约或数量细节 | 登记其所属后续阶段；当前只保留它与现阶段概念的必要连接。 |
| 相邻模块事实 | 只读取已确认的输入、输出或责任契约；不讨论相邻模块内部逻辑。 |
| 用户明确要求改主线或改阶段 | 暂停原链路，先按路线图判断是否需要调整。 |

## 我方执行闸门

每次回复前由 Codex 自行核验，不要求用户承担检查工作：

- 本轮是否直接服务于 T4 当前阶段目标；
- 输入是主线内容、结构前提、后续桩子还是相邻业务边界；
- 是否把补充材料、验证载体或后续机制误说成当前“下一步”；
- 是否重复询问已确认内容；
- 是否在没有稳定结论时写入正式资料。

任一项不成立时，不切换讨论目标：先说明材料归位，再回到当前未完成的主线问题。

## 写入边界

对话中的推演、样例和临时表达不自动写入资料。只有用户确认的业务结论，或可由当前有效资料直接推出且不改变业务取舍的结论，才按其归属写入对应资料池；本控制卡本身不记录库存业务事实。
