# 侧边对话承接与退出协议 v0.1

> 状态：当前有效的项目治理协议。
>
> 作用：让任一模块的侧边对话在用户要求退出或交接时形成可独立承接的资料包；本协议不保存业务事实，也不改变模块启动状态。

## 1. 适用对象与资料身份

侧边对话可用于局部探讨、访谈审阅、构想验证或主对话之外的连续讨论。它可以建立实时讨论承载文件，用于防止对话窗口关闭后丢失已讨论内容。

实时讨论承载、Web 子承载和冻结继承包均不是模块正式资料。它们只保存来源、用户输入、推导、探索、桩子、冲突、建议去向和恢复点；未经用户确认并写入正式资料，不得作为业务事实、页面、接口或实现依据。

## 2. 两种承载状态

| 状态 | 用途 | 后续动作 |
|---|---|---|
| 讨论中 | 侧边对话持续追加的实时承载，可包含一个或多个子承载 | 用户可继续在当前或新侧边对话讨论；不得直接正式化 |
| 已冻结待承接 | 用户发起退出／交接后形成的独立继承包 | 新侧边对话或主对话按包内恢复点承接；主对话逐项决定正式去向 |

## 3. 用户发起的退出与交接

用户说“结束侧边对话”“形成继承文件”“交给主对话”或等效表达时，立即触发交接。交接不要求讨论完成、模块启动或业务结论正式化。

助手必须在当前可用上下文中：

1. 冻结一份独立继承包，并从实时承载中定位全部相关子承载；
2. 在[侧边对话承接索引](../progress/侧边对话承接索引.md)登记包的位置、所属主题、状态和后续路由；
3. 在适用日报记录本次交接，不把业务候选写成日报事实；
4. 明确新侧边对话和主对话各自的读取入口；
5. 不因交接自动更新模块规则、接口、页面、范围登记或 Web 启动状态。

## 4. 冻结继承包的最小内容

每份继承包必须可脱离侧边聊天独立阅读，至少包括：

1. 来源范围、建立日期、所属模块／主题和资料身份；
2. 当时使用的正式基线及其作用；
3. 用户明确输入；
4. 基于正式资料的直接推导；
5. 探索构想、桩子和冲突；
6. 已知子承载、外部材料和明确不继承内容；
7. 建议的正式资料去向、当前恢复点和下一项唯一讨论任务；
8. 新侧边对话与主对话的可选承接方式。

## 5. 后续路由

### 新侧边对话继续

新侧边对话先从索引定位冻结继承包，再建立新的实时讨论承载。新讨论可以提出候选，但不能因读取继承包自动把候选升级为正式事实。

### 主对话承接

主对话先读取冻结继承包和对应正式基线，逐项确认来源、责任、正式结果、跨模块影响及资料归属。确认后才写入模块规则池、接口池或未来模块资料；未确认内容保留为桩子或探索。

## 6. 完成与引用

包的位置与状态见[侧边对话承接索引](../progress/侧边对话承接索引.md)。主对话处置全部可采纳内容并登记正式去向或不采用理由后，索引标为“已主对话接收”或“已退出”；原包只作追溯。未冻结旧聊天的迁移仍按项目历史迁移硬闸门处理。
