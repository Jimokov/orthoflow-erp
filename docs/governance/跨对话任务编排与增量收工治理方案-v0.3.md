# 跨对话任务编排与增量收工治理方案 v0.3

> 状态：当前有效治理方案
>
> 生效日期：2026-08-28
>
> 取代：`v0.2`。本次只修复并行对话的任务归属与驾驶舱语义，不改变任何模块业务事实。

## 1. 核心模型

项目活动任务是集合 `T = {T1, T2, …, Tn}`。每个 `Tn` 只在任务矩阵中登记其任务关系、正式入口、状态、恢复点、依赖和绑定对话；业务事实仍只在模块正式资料中。

项目驾驶舱展示活动集合与项目排序。项目排序不表示项目只有一个任务，更不表示任何对话应自动切换到该任务。

一个活动对话在同一时刻只能绑定一个 `Tn`；一个 `Tn` 的日常业务推进也只能由其绑定对话进行。共享资料、跨模块候选机制和项目索引可以被多个 `Tn` 使用，但不是可绑定或可抢占的独立任务。

## 2. 绑定、续接与切换

| 情形 | 必须动作 | 禁止动作 |
|---|---|---|
| 对话已有绑定，用户未点名模块 | 续接已绑定 `Tn` | 用驾驶舱主线、任务排序或其他任务状态替换绑定 |
| 用户明确指定另一任务 | 先在任务矩阵更新本对话绑定，再读取新任务正式资料 | 先展开新模块业务，再补登记切换 |
| 新对话尚无绑定 | 只完成项目任务脉冲，显示可承接任务并等待用户指定或建立绑定 | 猜测用户意图、读取任一模块正文或形成业务结论 |
| 任务暂停 | 保留该 `Tn` 与恢复点；其绑定对话只在用户恢复后继续 | 用其他活动任务自动填补该对话 |
| 共享机制触发 | 在当前 `Tn` 内按共享资料规则登记或引用 | 将共享机制登记成新的对话任务或切换理由 |

任务矩阵中的系统线程 ID是绑定的唯一技术定位；标题只作人工核验。运行时暂不能读取线程 ID时，必须先以用户明确的对话任务意图建立临时绑定，并在可获得 ID 后补齐；未建立临时绑定不得进入模块正文。

## 3. 新对话与每日开工协议

1. 读取驾驶舱、任务矩阵、最近有效日报，完成项目任务脉冲；
2. 找到本对话的绑定 `Tn`，并核对其仍为活动任务；
3. 用户本条未明确切换时，锁定该 `Tn`；用户明确切换时，先更新绑定；无绑定时停止在任务脉冲；
4. 只读取锁定 `Tn` 的范围登记、模块总池和直接相关正式资料；
5. 核对该任务内部的唯一任务、恢复点、直接依赖和不进入范围；
6. 首条业务推进回复说明：绑定任务、并行任务、为何不进入并行任务、当前恢复点与待决定事项；
7. 业务、资料写入、收工均只作用于锁定 `Tn`；项目共享索引仅作必要的增量合并。

完成标准：可以从任务矩阵证明“当前对话为何推进这个 `Tn`”，并可证明没有读取或改写其他 `Tn` 的模块正文。任何一项不能证明时，不启动业务。

## 4. 驾驶舱与矩阵职责

| 资料 | 回答的问题 | 不回答的问题 |
|---|---|---|
| 驾驶舱 | 哪些任务活动、项目排序是什么、各任务下一入口在哪里 | 当前对话应该自动推进哪个任务 |
| 任务矩阵 | 每个 `Tn` 的绑定对话、正式入口、状态、恢复点与依赖 | 各模块业务事实 |
| 模块正式资料 | 当前任务的业务事实与阶段边界 | 项目全部任务的排程 |

项目级“当前唯一任务”这一表达停用。只允许在某个明确 `Tn` 的正式入口中使用“该任务内部唯一任务”。

## 5. 防撞验收

以下场景必须全部通过，任一失败即停止受影响任务的业务推进并修复治理资料：

| 场景 | 期望结果 |
|---|---|
| T1 对话收到“开启今日工作”，驾驶舱排序为 T2 | 只续接 T1；T2 仅在任务脉冲中说明 |
| T1 对话收到“切换到 T2” | 先更新绑定，再承接 T2 |
| 新对话收到“开启今日工作”，没有绑定和模块指令 | 不读模块正文，只请求或建立绑定 |
| T1 暂停，T2 活动 | T1 对话保持暂停，不自动转做 T2 |
| T1 产生库存相关候选 | T1 按候选机制登记；不占用 T2 对话、不把候选当库存事实 |
| 两个任务先后更新共享索引 | 后者先读取前者最新版本，只合并任务关系，不覆盖对方状态 |

## 6. 收工与修订

收工仍按《多任务并行收尾与提交方案 v0.1》执行：当前对话先收尾其绑定 `Tn`，再增量核对项目活动集合。任务切换、暂停、恢复、绑定丢失或绑定冲突均先更新任务矩阵；需要跨端承接的治理变更须限定范围提交、推送并验证。

本规则不要求每次回复重复绑定信息，也不限制业务讨论的自然表达；只在新对话、首次开工、切换、暂停／恢复、资料冲突或资料写入时触发核验。
