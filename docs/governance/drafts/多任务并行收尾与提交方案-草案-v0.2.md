# 多任务并行收尾与提交方案 v0.2

> 状态：冻结的未通过草案；不是当前有效规则，不得被 `AGENTS.md`、进度资料或业务任务引用。
>
> 生效日期：2026-08-28
>
> 保留原因：其“任务当日工作、任务生命周期、项目记录对齐须分别判断”的原则已以最小改动并入 `多任务并行收尾与提交方案 v0.1`；其余扩展内容未获采用。
>
> 修订目的：分离任务当日收工、项目记录对齐和任务生命周期，避免把共享资料待提交误报为用户仍需继续业务工作。

## 一、适用模型

项目活动任务表示为集合：

```text
T = {T1, T2, T3, …, Tn}
```

每个 `Ti` 可以是业务模块任务、跨模块治理任务、候选沉淀任务或保留明确恢复点的暂停任务。

- `Ti` 的业务事实只存在于所属正式资料；
- 任务矩阵记录任务关系、绑定、阶段、恢复点和下一入口；
- 根 `README.md` 摘要项目活动任务集合和排序，不代表项目只有一个任务；
- 任务生命周期仍可处于进行中、暂停、等待确认或阻塞状态；生命周期未完成不等于当天没有收工。

## 二、四个必须分开的状态

### 1. 任务当日工作状态

只回答当前任务今天是否结束工作：

- 今日已收尾；
- 今日未收尾，并说明缺口和恢复点；
- 今日阻塞，说明阻塞原因和恢复条件；
- 今日状态未核验。

“今日已收尾”不表示任务生命周期完成。

### 2. 任务生命周期状态

记录任务仍处于进行中、暂停、等待确认、阻塞或已完成等生命周期状态。生命周期状态不能被用来推断当天工作是否收尾。

### 3. 项目记录对齐状态

只回答本次任务相关的资料、索引和远端是否完成整理：

- 已对齐；
- 待合并；
- 待提交；
- 待推送；
- 待远端验证。

共享资料待合并或待提交，不等于当前任务今日未收尾，也不要求用户继续完成其他业务模块。

### 4. 今日全部任务工作状态

汇总活动任务集合 `T` 的当日工作状态。这里沿用输出标签“今日全部项目”，但其含义是“今日全部活动任务的工作收尾状态”，不是所有模块生命周期完成，也不是软件整体完成。

只有每个活动任务的当日状态都明确后，才可以汇总为“今日全部任务工作均已收尾”。状态未核验时必须如实标记，不能按任务仍处于活动状态推断为未收工。

## 三、用户的收工指令

用户说“结束当日工作”时，含义是结束当前对话负责的任务在当天的工作。它不自动表示：

- 当前任务生命周期完成；
- 所属模块完成；
- 全部活动任务完成；
- 所有共享资料已经提交并推送。

助手只处理当前绑定任务，并增量核对项目记录；不得借此自动切换到其他任务或要求用户继续设计全部软件。

## 四、收工回复要求

收工回复必须让以下范围可区分，可保留自然表达，不要求其他业务回复使用固定模板：

```text
该任务：当前任务今日工作状态
该项目：当前任务相关项目记录对齐状态
今日全部项目：全部活动任务今日工作收尾状态
```

必要时另行说明当前任务生命周期状态。

不得单独使用“今日全部项目：未收口”而不说明原因。若未收口是因为共享记录或远端同步，应明确写成“各任务今日工作已收尾，项目共享记录待合并／提交／推送”，不能让用户误以为业务尚未完成。

## 五、收工流程

### 1. 当前任务收尾

当前对话只负责其绑定的 `Ti`：

1. 确认 `Ti` 今日实际完成内容、未闭合桩子和恢复点；
2. 更新直接承载本次变化的正式资料；
3. 更新 `Ti` 的任务状态、恢复点和下一入口；
4. 在当日日报登记 `Ti` 的当日工作状态；
5. 有跨模块变化时登记依赖、回写或待论证项。

当前任务可以在共享资料尚未提交时完成“今日工作已收尾”，但必须把项目记录状态标为待对齐。

### 2. 当日日报中的任务状态登记

当日存在两个或以上活动任务时，在当日日报中维护一张简短登记表：

```text
| 任务 | 今日工作状态 | 生命周期状态 | 项目记录状态 |
```

该表只记录当日行政收尾状态，不保存模块业务事实。后续任务收工时，先读取并增量合并已有登记，不覆盖其他任务。

### 3. 项目记录增量对齐

只检查本次变化是否影响：

- 活动任务集合、绑定、阶段、恢复点或下一入口；
- 驾驶舱摘要；
- 当日日报和任务矩阵；
- 需要跨对话或跨端继承的资料。

不因一个任务收工而重读或改写其他模块正文。

### 4. 全部任务汇总

逐项读取当日日报或其他当前可复查登记：

- 今日已收尾；
- 今日未收尾；
- 阻塞／暂停／待承接，且恢复信息完整；
- 状态未核验。

“今日全部项目”只汇总上述当日状态。项目记录是否已提交、推送和验证，另在“该项目”或项目记录状态中报告。

## 六、共享资料与工作区改动

工作区出现改动时，先按来源分类：

- 当前任务所属正式资料；
- 其他任务所属资料；
- 多任务共同维护的日报、任务矩阵、治理入口等共享资料；
- 无关临时文件、实验文件或未跟踪产物。

分类结果只决定提交边界，不决定任务当日是否收工。

- 其他任务的改动不得混入当前任务提交；
- 共享资料需要合并时，后收工任务先读取最新内容并只合并自己的变化；
- 无法安全合并时，标记“项目记录待合并”，不撤销已经确认的任务当日收尾；
- 无关临时文件不纳入本次治理提交，也不作为项目未收工依据。

## 七、Git 提交与远端同步

### 1. 提交边界

只提交本次任务和本次治理明确涉及的文件。已有其他任务改动、低保真、草稿、实验文件和临时目录必须排除。

### 2. 收工与提交的关系

任务当日工作可以先收尾，资料提交和远端同步随后作为项目记录对齐动作处理。远端尚未同步时：

- 可以报告当前任务今日已收尾；
- 必须报告项目记录待提交／待推送／待验证；
- 不得报告项目记录已对齐；
- 不得把该状态解释为用户仍需完成业务设计。

### 3. 治理发布顺序

```text
形成最小变更清单
→ 用户确认治理范围
→ 修改治理文件与适用进度记录
→ 检查共享文件冲突
→ 限定范围提交
→ 推送远端
→ 验证远端包含提交
```

提交失败或无法验证时，保留本地状态并明确恢复条件，不扩大提交范围。

## 八、失败与恢复

- 任务当日状态未知：报告“状态未核验”，暂停全部任务收工汇总，不猜测；
- 任务生命周期仍活动：不能据此认定今日未收工；
- 共享文件冲突：只暂停项目记录对齐，保留各任务已登记的当日状态；
- 远端同步失败：报告项目记录未对齐及恢复条件，不要求继续业务设计；
- 资料不足：登记桩子或未收尾状态，不用聊天记忆补全。

## 九、验收标准

至少验证以下场景：

- T1、T2 分别宣布当日收工后，均可登记为“今日已收尾”，即使 T1、T2 生命周期仍为活动；
- 日报和编号登记等共享文件未提交时，报告“项目记录待对齐”，不报告“任务未收工”；
- 其他任务的治理改动、侧边承接文件和临时文件不会混入当前任务提交；
- 未收尾、暂停、阻塞和状态未核验任务均能分别说明；
- “该任务”“该项目”“今日全部项目”不再互相替代；
- 用户不需要因项目记录待对齐而完成全部模块设计；
- 远端同步完成后，能单独确认项目记录对齐，而不改变任务生命周期状态。

## 十、落地边界

本方案只治理并行任务的当日收工、共享资料和 Git 报告口径，不修改：

- 任一业务模块的规则、接口、页面、库存或后台能力；
- 活动任务绑定和编号规则；
- 任务的生命周期完成条件；
- 历史对话或旧资料的事实身份。
