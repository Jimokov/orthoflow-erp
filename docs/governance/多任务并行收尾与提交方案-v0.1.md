# 多任务并行收尾与提交方案 v0.1

> 状态：当前有效治理规则
>
> 生效日期：2026-08-28
>
> 作用：只规定并行任务的当日收工、项目记录对齐和限定范围提交；任务绑定与切换按《跨对话任务编排与增量收工治理方案 v0.3》及任务矩阵执行。

## 1. 收工的范围

用户说“结束当日工作”时，只结束当前对话绑定任务当天的工作；不表示该任务生命周期、所属模块或全部项目已经完成。

收工回复必须分别说明：

```text
该任务：当前任务今天是否收尾
该项目：本次相关资料、索引和远端是否对齐
今日全部项目：全部活动任务今天的状态是否均已明确
```

- 当前任务当天已收尾，不等于其生命周期完成；
- 共享资料待合并、待提交或待推送，应在“该项目”说明，不改报为任务未收尾；
- “今日全部项目”只汇总活动任务的当日状态，不判断软件或模块是否完成。

## 2. 最小收工动作

1. 确认当前任务当天实际完成内容、未闭合桩子和恢复点；
2. 更新直接承载本次已确认结论的正式资料及当日日报；
3. 仅在本次变化影响活动任务集合、恢复入口、项目排序、项目级门禁或跨任务条件时，增量更新任务矩阵、驾驶舱或其他共享索引；
4. 只提交当前任务和本次治理明确涉及的文件，排除其他任务改动、草稿、实验文件和临时产物。

不因一个任务收工而重读其他模块正文，也不以共享资料待处理推断用户还需继续业务设计。

## 3. 对齐与提交

项目记录已对齐，表示本次适用的资料、索引和远端状态已经完成整理；远端未同步时，可以报告当前任务当天已收尾，但必须报告项目记录待对齐，不能宣称跨端承接已完成。

多个任务先后更新共享资料时，后者先读取最新状态，只合并自己的增量；无法安全合并时，报告“项目记录待对齐”，不撤销已经确认的任务当日收尾。

## 4. 状态不明与恢复

无法确认某个活动任务的当日状态时，如实标记“状态未核验”并保留恢复点；在状态明确前，不报告“今日全部项目：已收口”。
