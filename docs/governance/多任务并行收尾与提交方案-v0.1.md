# 多任务并行收尾与提交方案 v0.1

> 状态：当前有效治理规则
>
> 生效日期：2026-08-28
>
> 目的：为任意数量的并行任务建立独立收尾、项目状态对齐、整体收口和 Git 提交边界，不把规则缩减为两个任务的特例。

## 一、适用模型

项目活动任务表示为集合：

```text
T = {T1, T2, T3, …, Tn}
```

其中每个 `Ti` 可以是一个业务模块任务、跨模块治理任务、候选沉淀任务或保留明确恢复点的暂停任务。

- `Ti` 的业务事实只存在于所属正式资料；
- 任务矩阵记录所有当前活动任务的来源、阶段、状态、恢复点和下一入口；
- 根 `README.md` 只摘要项目主线，不代表项目只有一个任务；
- 任务数量 `n` 不预设上限，也不因为当前只有少数任务而改变规则。

## 二、单句收工指令

用户每天可以在各个工作对话中使用同一句：

```text
结束当日工作
```

该指令的含义是结束当前对话负责的任务在今天的工作，不等于：

- 该任务生命周期完成；
- 所属项目完成；
- 全部项目已经收口。

收到后，助手自动完成当前任务收尾、项目状态增量对齐，并判断全部任务的整体收口状态。

## 三、三行固定结果

每次执行“结束当日工作”，结果必须清楚区分以下三个范围：

```text
该任务：
该项目：
今日全部项目：
```

### 1. 该任务

指当前对话正在负责的任务 `Ti`，报告今天的工作状态：

- 今日工作已收尾；
- 今日工作未收尾（说明缺口和恢复点）；
- 今日未改变业务基线（仍登记恢复点）。

“今日工作已收尾”不自动表示 `Ti` 已完成。

### 2. 该项目

指当前任务涉及的模块／业务项目，报告本日资料状态：

- 今日状态已对齐；
- 今日状态待对齐（说明缺失的资料、索引或同步）。

该项与“该任务”是并列状态：前者判断工作，后者判断资料与项目状态。

### 3. 今日全部项目

指活动任务集合 `T` 的整体判定：

- 今日已收口：所有活动任务都已完成当日收尾，或明确进入暂停、阻塞、待承接状态，且项目索引和远端状态已对齐；
- 今日未收口：列明尚未完成当日收尾或尚未对齐的任务。

存在暂停或阻塞任务并不自动阻止整体收口，前提是它们已有明确状态、恢复点和下一入口。

## 四、任意数量任务的收尾流程

### 1. 当前任务收尾

当前对话只负责 `Ti`：

1. 确认 `Ti` 今天实际完成的内容；
2. 更新直接承载结论的模块资料；
3. 更新 `Ti` 的任务状态、恢复点和下一入口；
4. 更新当日日报；
5. 对涉及跨模块的变化登记依赖、回写或待论证项。

不能因为 `Tj`、`Tk` 尚未收尾而把 `Ti` 的工作留在聊天中，也不能替其他任务静默补写业务事实。

### 2. 项目状态增量对齐

每个 `Ti` 收尾后，仅检查项目级索引是否发生变化：

- 活动任务集合是否增加、减少、暂停或恢复；
- 项目主线、阶段或硬闸门是否变化；
- 驾驶舱是否滞后；
- 其他任务是否受到直接依赖影响；
- 是否有需要跨对话或跨端继承的资料变化。

这一步不重读 `T` 中其他任务的全部业务资料。

### 3. 全部任务收口判断

把任务矩阵中当前活动任务逐项检查为：

- 今日已收尾；
- 今日未收尾；
- 暂停／阻塞／待承接，且恢复信息完整。

只有集合 `T` 中没有未说明状态的任务，且项目级资料已对齐，才报告“今日全部项目：已收口”。

## 五、多个任务先后收尾

任务可以按任意顺序收尾，不要求等待其他任务：

```text
Ti 收尾 → 项目状态增量对齐
Tj 收尾 → 项目状态增量对齐
Tk 收尾 → 项目状态增量对齐
……
最后一个任务收尾 → 判断今日全部项目是否已收口
```

如果某个任务先收尾而其他任务仍活动，应明确报告：

```text
该任务：今日工作已收尾
该项目：今日状态已对齐
今日全部项目：未收口（仍有活动任务未完成今日收尾）
```

## 六、共享资料与并行写入

### 1. 模块资料

每个任务优先提交自己所属模块的正式资料，避免跨任务混入业务事实。

### 2. 项目共享资料

`README.md`、任务矩阵、当日日报、治理索引等共享资料必须合并所有任务的变化：

- 后收尾任务先读取前一任务的最新状态；
- 不得用旧副本整文件覆盖其他任务的登记；
- 发生冲突时合并任务状态，保留各自恢复点和下一入口；
- 无法安全合并时，暂停项目整体收口判断并报告冲突。

### 3. 活动任务增删

新增 `Tn+1`、暂停 `Ti`、恢复 `Tj` 或关闭任务时，应先更新任务矩阵，再在项目状态中反映集合变化。未登记的任务不得被当作已收口。

## 七、Git 提交与远端同步

### 1. 提交范围

每次任务收尾只提交：

- 当前任务所属正式资料；
- 当前任务行和必要的项目索引变化；
- 当日日报中对应的实际变化；
- 为保持索引一致性而必须更新的治理或入口文件。

工作区中与本任务无关的低保真、草稿、实验文件或其他模块改动不得混入。

### 2. 提交时机

- 当前任务产生需要跨对话／跨端继承的资料变化时，提交并推送；
- 只有讨论、没有资料变化时，不制造形式提交；
- 项目整体收口前，确认所有需要继承的任务变化已经进入远端。

### 3. 提交顺序

```text
任务资料整理
→ 当前任务索引更新
→ 项目状态增量对齐
→ 限定范围提交
→ 推送远端
→ 验证远端包含提交
```

远端未同步时，可以报告当前任务已本地收尾，但不得报告跨端承接完成或今日项目整体已收口。

## 八、失败与恢复

- **任务漏登记**：暂停全部项目收口判断，补登记任务来源、状态和恢复点；
- **任务状态冲突**：以最新正式资料和任务矩阵为准，合并后再判断收口；
- **共享文件冲突**：只暂停受影响的项目索引更新，不回退或覆盖无关任务资料；
- **远端同步失败**：保留本地提交，标记跨端未完成及恢复条件；
- **任务资料不足**：登记桩子或未收尾状态，不用聊天记忆补全。

## 九、标准输出示例

### 当前任务先收尾，仍有其他任务活动

```text
该任务：今日工作已收尾（库存管理启动前审校）
该项目：今日状态已对齐
今日全部项目：未收口（仍有其他活动任务未完成今日收尾）
```

### 所有活动任务均已明确状态

```text
该任务：今日工作已收尾
该项目：今日状态已对齐
今日全部项目：已收口
```

### 当前任务尚未整理完成

```text
该任务：今日工作未收尾（待补齐正式资料登记）
该项目：今日状态待对齐
今日全部项目：未收口
```

## 十、验收标准

使用当前项目实际活动任务集合执行一次实验，任务数量不固定，至少验证：

- 新增或并行存在的全部 `T1…Tn` 均可从任务矩阵定位；
- 任意一个任务收尾不会覆盖其他任务状态；
- 每个任务均能独立得到三行结果；
- “该任务”“该项目”“今日全部项目”三种状态不会混为一谈；
- 未收尾任务、暂停任务、阻塞任务和待承接任务均有明确说明；
- 项目整体只有在全部任务状态明确、索引对齐、必要远端同步完成后才报告已收口；
- 过程不要求全项目全量重读，不把未确认业务内容写入正式资料。

## 十一、落地范围

本方案生效后，执行以下范围：

1. 三行收尾结果原则写入 `AGENTS.md`；
2. 多任务集合、项目状态增量对齐和提交范围写入进度规范；
3. 任务矩阵补足活动任务的定位信息；
4. 不修改任何模块业务规则，不自动关闭已有任务，不回写旧对话。
