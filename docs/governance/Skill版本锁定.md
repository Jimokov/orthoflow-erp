## 职责边界

- 独立 Skill 仓库只承载可跨项目复用的推进方法、检查闸门、版本与行为回归案例。
- 本项目的业务事实、模块范围、资料路径、对话编号、进度管理和项目专属硬闸门只承载于 `AGENTS.md` 与项目资料池。
- 项目内副本是锁定版本的可执行快照，不是第二条研发线；不得在其中直接增加语义规则或独立递增版本。

## 强制校验

1. 调用 `$advance-business-module` 前，读取本文件与项目内副本的 `VERSION`；正式回复须报告实际读取路径与版本。
2. 若项目内 `VERSION`、文件内容或锁定提交无法对应本表，停止业务推进，先报告“Skill 来源／版本不一致”。
3. 通用规则变更必须先在独立仓库完成：修改、行为案例、校验、版本更新、提交、标签、GitHub Release 与远端验证；随后才可同步项目快照并更新本文件。
4. 项目专属规则只能改项目 `AGENTS.md` 或项目资料；不得以“项目 Skill 新版”名义写入本地副本。

## 发生分叉时的恢复

1. 冻结业务提问与项目内 Skill 改动；
2. 记录实际路径、实际 `VERSION`、锁定版本及差异文件；
3. 将差异分类为通用规则或项目专属规则：前者回独立仓库发布，后者迁入项目规则；
4. 用已发布标签的完整快照恢复项目副本，更新本锁定记录并完成限定范围的 Git 同步；
5. 新会话重新读取实际生效副本，确认版本与来源后才恢复业务推进。

本文件不替代 Skill 内容，也不保存业务规则；它只证明项目当前允许使用哪一个通用 Skill 快照。
