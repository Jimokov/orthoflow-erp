# 治理变更与回滚基线

## 当前状态

项目以根 `AGENTS.md`、项目治理资料和各模块当前有效资料池作为业务推进依据；不设置项目内业务推进 Skill 作为调用前提、版本锁定或验收依据。

## 回滚基线

- 重构前标签：`governance/pre-advance-business-module-retirement-2026-08-26`
- 标签用途：仅在确认项目原生治理不可用时，用于检索重构前的治理文件与本地快照。
- 恢复原则：先从标签比较需要恢复的具体规则，再以新的治理提交恢复；不得直接覆盖当前模块业务资料。

## 变更记录

- 2026-08-26：根 `AGENTS.md` 去除外部工作流调用、版本锁定、固定编号和局部追问语义，改为项目原生的宏观审查、自然对话与成组提问约定。
- 2026-08-28：发布《跨对话任务编排与增量收工治理方案 v0.2》，将项目级活动任务发现、模块正式资料承接、两层增量收工和“事实—判断—建议”盘点回复原则纳入项目治理；不改变模块业务事实，不要求全项目全量重读。
- 2026-08-28：编号规则由“自然日项目全局序号”调整为“对话线程内连续序号 + Codex 系统线程 ID追溯”，以避免并行对话共享 Markdown 计数器造成竞态、漏记和误报；旧全局序列仅保留历史追溯。
- 2026-08-28：进一步将可见标识调整为“本日对话编号”：每个自然日新开启或首次恢复的对话线程分配一个编号，该线程当天所有可见回复沿用；系统线程 ID继续作为跨对话、跨端唯一身份，旧回复序号仅保留历史追溯。
- 2026-08-28：经用户澄清，以上线程级调整撤回为历史误改；正式规则恢复为“本日对话 NN”作为自然日跨所有对话共享的可见回复序号，仅将显示名称由“本对话回复”改为“本日对话”，系统线程 ID继续用于跨对话追溯。
