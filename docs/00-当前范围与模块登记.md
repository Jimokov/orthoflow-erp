## 二、当前没有登记为正式模块的内容

以下内容不得因为“常见 ERP 应该有”或“模板预留了位置”而被自动创建：

- 未经讨论的 APP 功能模块；
- 未经讨论的 Web 后台模块、角色、审批、采购、仓库或报表能力；
- 从行业产品中推测出来、但尚未被本项目确认的业务流程；
- 为了让文档看起来完整而补写的页面、状态、字段和异常分支。

今后确实讨论到新模块时，先更新本登记，再决定是否建立对应总池。

## 三、成熟度与建池规则

### 1. 完整构想不等于全部封板

一个模块即使已有完整构想，也可以仍有局部未决问题。总池必须把“当前有效结论”和“待讨论问题”分开，不能用整理动作替代业务确认。

### 2. 概念登记不等于建立模块

库存管理目前只能登记“存在这个方向”。在业务边界和基本规则尚未讨论前，不创建它的规则池、设计池、代码池或页面目录。

### 3. APP 与 Web 分开建池

APP 已有构想，不代表相应 Web 后台已经被定义。两端可以互相引用已确认的接口，但不能由一端资料自动推演另一端功能。

### 4. 总池不是一份巨型文档

总池是该模块资料的入口和索引。规则、设计、代码、验收与历史分别保存，总池首页只说明边界、当前有效版本、阅读顺序和未决问题。
