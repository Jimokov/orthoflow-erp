今后确实讨论到新模块或跨端业务域时，先更新本登记，再决定是否建立对应总池。

## 三、成熟度与建池规则

### 1. 完整构想不等于全部封板

一个模块即使已有完整构想，也可以仍有局部未决问题。总池必须把“当前有效结论”和“待讨论问题”分开，不能用整理动作替代业务确认。

### 2. 启动资料不等于形成业务规则

库存管理已按用户指定建立启动资料，并完成全量排查与推进基线审校。两份启动控制资料已确认，当前进入业务边界与核心对象澄清；当前规则基线仍只包含外部约束与待确认启动输入。未逐项确认前，不创建设计池、代码池或页面目录，也不把输入写成库存规则。

### 3. APP 与 Web 分开建池

APP 已有构想，不代表相应 Web 后台已经被定义。两端可以互相引用已确认的接口，但不能由一端资料自动推演另一端功能。

### 4. 总池不是一份巨型文档

总池是该模块资料的入口和索引。规则、设计、代码、验收与历史分别保存，总池首页只说明边界、当前有效版本、阅读顺序和未决问题。
