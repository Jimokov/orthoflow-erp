# 总池启用与变更检查表

## 新建一个模块总池前

- [ ] 这个模块或范围已经被用户明确提出；
- [ ] 已说明它属于 APP、Web 或其他哪一端；
- [ ] 已分清“已有完整构想”“概念阶段”和“未讨论”；
- [ ] 用户已经同意为它建立总池；
- [ ] 没有把常见行业功能当成本项目既定功能；
- [ ] 没有因为 APP 已讨论，就自动补写 Web 后台；
- [ ] 只准备启用有真实资料支撑的子池。

任何一项不满足，都只登记现状，不实例化模块总池。

## 迁移旧资料时

- [ ] 已完成来源文件盘点；
- [ ] 已区分当前有效、待确认、参考和历史版本；
- [ ] 已确认文件之间没有互相冲突，或已把冲突列入待办；
- [ ] 没有把尚未完成的页面或流程标记为封板；
- [ ] 总池首页已给出唯一的当前阅读入口；
- [ ] 原始资料保留来源，不通过整理动作篡改业务含义。

## 新增或修改内容时

- [ ] 变更来自新的讨论结论或真实实现结果；
- [ ] 已判断变更属于规则、接口、设计、代码、验收还是历史；
- [ ] 若影响其他模块，只登记影响，不擅自修改对方模块；
- [ ] 若规则与设计冲突，先回到规则层确认；
- [ ] 若只是设想，仍放在待讨论区，不提升为正式规则。

## 启动 APP 全链路汇总前

- [ ] 参与测试的模块已经分别建立自己的总池；
- [ ] 每个模块都有清晰边界和当前有效资料；
- [ ] 模块间真实存在的接口已经确认；
- [ ] 测试场景只使用已确认能力；
- [ ] 尚未讨论的库存或 Web 能力没有被当作既有条件。
