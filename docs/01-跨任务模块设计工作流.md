# 跨任务模块设计工作流

## 一、目标

让每个新任务不依赖上一段长对话，也不因切换到手术植入、库存或其他模块而丢失已确认规则。系统要做到两件事：

1. 新任务知道从哪里读取当前事实；
2. 新模块只继承前一模块真正对外输出的结果，不复制其内部流程。

## 二、三层结构

| 层级 | 项目中的载体 | 作用 |
|---|---|---|
| 自动入口 | 根目录 `AGENTS.md` | 新任务进入本项目时，先执行统一约束并启用业务模块推进 Skill |
| 工作流 | `$advance-business-module` | 识别模块成熟度、按需读取资料、控制阶段、沉淀结果 |
| 知识与状态 | 范围登记及各模块总池 | 保存当前有效规则、接口、设计进度、代码和历史来源 |

它与扣子式工作流的思想相似：资料池相当于知识库，Skill 相当于工作流编排，总池首页相当于当前节点与变量。但这里不需要建设新的工作流软件，先用项目文件和 Codex 原生机制实现即可。

## 三、为什么不能只做 Skill

Skill 适合保存“每次怎样工作”，不适合把所有模块的完整业务规则长期塞进自身。那会导致：

- Skill 越来越长，每个任务都加载无关内容；
- 规则版本变化后，Skill 和业务文档容易不一致；
- 手术通知的内部细节会污染手术植入或库存设计。

因此 Skill 只保存步骤和边界，真实业务放在对应总池中。

## 四、为什么还需要 AGENTS.md

仅靠用户每次输入 `$advance-business-module` 容易遗忘。项目根目录的 `AGENTS.md` 负责要求 Codex 在本项目的新任务开始时先使用该 Skill。只要新任务仍以本项目为工作区，用户不需要每次手工添加前缀。

如果在完全脱离本项目目录的新任务中工作，项目指令和项目内 Skill 不会自动出现。这时应先打开本项目，或明确引用本项目路径和 `$advance-business-module`。

## 五、新模块启动流程

1. 在范围登记中确认模块名称、所属端和成熟度；
2. 若只是概念阶段，先讨论业务，不生成页面和代码；
3. 有真实资料后，建立该模块总池；
4. 从关联模块的“跨模块接口摘要”读取必要输入；
5. 只把已确认输入写进新模块，不继承来源模块内部流程；
6. 按规则、封板、信息架构、页面清单、页面流程、低保真、视觉、代码、验收逐级推进；
7. 每次讨论结束更新总池的当前阶段和下一步。

## 六、手术植入为何曾经继承不好

此前主要依靠对话交接和大段背景材料，没有一个稳定的“来源模块输出契约”。即便带入手术通知讨论，新任务也需要自己从大量内容中判断哪些与手术植入有关，容易遗漏或错误复制。

现在手术通知总池增加了“跨模块接口摘要”。未来建立手术植入总池时，先读取这份摘要，再用手术植入自己的规则决定如何接收、校验和使用这些输入。这样继承的是边界和结果，不是上一模块的整段对话。
